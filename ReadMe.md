## 项目简介

**征纳互动人数和在线监控** 是一个油猴用户脚本（UserScript），用于实时监控 [征纳互动平台](https://znhd.hunan.chinatax.gov.cn:8443/) 的等待人数和在线状态。当有纳税人等待时自动语音播报提醒，支持自定义常用语快速回复，帮助坐席人员及时响应。

### 核心特性

- **实时人数监控**：每 3 秒自动检测等待人数，有人等待时语音播报提醒
- **掉线检测**：自动检测平台掉线弹窗，及时语音告警
- **语音播报**：基于 Web Speech API，支持一键开关，带语音队列管理避免播报冲突
- **常用语管理**：从远程 YAML 配置文件加载常用语，数据源地址可在设置面板自定义，支持关键字搜索过滤，一键复制并填入 TinyMCE 编辑器；内置 2 小时本地缓存，相同数据源在有效期内打开弹窗不再重复请求
- **工作时间限定**：仅在工作时间段（默认上午 9:00-12:00，下午 13:30-18:00，可在设置面板调整）内执行监控，非工作时间自动暂停
- **传输助手（手机 ↔ 电脑互传）**：主面板「传输助手」打开独立三栏窗口（v26.10.12-v4 起对齐**微信桌面版暗色**；v5 起标题条与第一栏同色、窗口整体放大 20%，v26.10.13-v1 起再缩小 10%）：顶部**标题条**右侧是自绘**关闭按钮**（悬浮变红）；**第一栏**窄图标导航（顶部 logo，下面对话 / 文件，底部设置 / 企业信息，只放图标不显示文字）；**第二栏**搜索框 +「+」按钮 + 会话列表；**第三栏**按选中会话聊天。手机扫码或打开本机专属链接上传（前端自动压缩），内容经中继服务器转发到本机并按设置自动弹出窗口；图片在会话里点「复制到剪贴板」即可在征纳互动 Ctrl+V 粘贴；每台电脑有稳定独立的设备 ID，A、B 各自链接互不影响；**多台手机同时在线时，每台发来的内容归入各自的会话**（按发送者手机 ID 归组，v26.10.13-v6）；**会话记录持久化在本机**（IndexedDB，仅保留最近 7 天，超期自动清理）；手机端页面 v26.10.12-v5 起改为与第三栏同款的**聊天窗**；**支持任意文件互传**（v26.10.14-v6，单次上限 100MB，文件不压缩、会话里显示为可下载的文件卡片，与图片各占一个入口）
- **网页图片嗅探**：主面板「图片嗅探」一键扫描当前网页上的图片（普通图片与懒加载属性、CSS 背景图；内联 SVG 也在采集范围内，但默认被后缀规则排除），**默认按会话（纳税人）分组展示**——读取征纳互动工作台的会话数据，把每张图归到它所属的会话窗口，**当前会话置顶**、认不出归属的进「未归属会话」，组头显示「会话名（N 张）」并可一键「全选本组」（普通网页上没有「会话」概念时自动退回平铺列表，不显示组头）；**组内按消息时间从新到旧排列**（v26.10.16-v2，最新发的图排最前；取不到消息时间的图 —— 例如未归属组 —— 退回旧口径按体积从大到小），可放大预览、单张下载、批量下载，或按 A4 版式打印（每张缩略图**右下角的图标按钮**「下载 / 打印」鼠标移上去才出现，悬停时用提示文字说明）；最小体积阈值（默认 20 KB）可在面板内调整并记住（小于阈值的图只被过滤，不显示也不参与全选/批量下载），大小未探明的图片折叠保留不丢；名字含 `znhd-sniff` / `user-woman` / `user-man` 或以 `.svg` 结尾（含内联 SVG）的图片在扫描阶段即被排除（**v26.10.16-v1 起不再显示排除计数**；卡片也不再显示文件名，只显示大小与尺寸；**v26.10.16-v3 起没拿到消息时间的图四周加一层红圈**，一眼能看出哪些图是「不知道什么时候发的」）。**体积测量 perf 优先（v26.10.14-v2）**：脚本启动即把 performance 资源表缓冲扩容并起 observer 持续预收，扫描时先按 URL 查预收数据（`decodedBodySize → encodedBodySize → transferSize`，零请求），查不到才发 HEAD / Range；**测量也提前到后台（v26.10.14-v4）**：脚本启动 5 秒后在后台把页面上的图量一遍，之后每 60 秒补一轮新图（零成本项不发任何请求；单轮网络测量上限 60 张、并发 2），打开嗅探窗口时直接复用已测结果，不再当场等网络 —— **同源图仍然零请求，只有资源表拿不到字节数的跨域图会在没开窗时被测量**，介意可在设置里关掉「图片嗅探：先在后台预测量图片大小」；**批量下载走两段式流水线**（并发预取 + 串行间隔触发，失败自动重试、永久错误不重试）
- **操作日志**：面板内嵌日志查看器，按类型（信息/警告/成功/错误）着色显示
- **提示音反馈**：复制常用语时播放提示音，提供操作确认

> **图片嗅探的会话归属怎么来的**：征纳互动工作台是 Vue2 + Vuex 单页应用，脚本读它的「当前会话 + 当前会话的消息列表」拿到「哪个文件属于哪个会话」，再按**文件名**把扫描到的图对号入座（图片在页面 DOM 里的位置不可靠，不能按位置猜）。这套「文件名 → 会话」的映射记在 `localStorage` 的 `scriptCat_SniffConvIndex`（**只记映射不记图片地址**，按站点分开、30 天过期、最多 2000 条），所以**切走会话后再点「重新扫描」，之前那些图仍留在原来的分组里**。**同一会话不会被拆成两组（v26.10.14-v5）**：会话 ID 是逐张图片解析的，页面有一部分消息给得出群组 ID、另一部分给不出（刷新 / 历史懒加载渲染出来的那条路），给不出就只会退化成 `name:<会话名>` 回退键 —— 以前这会让同一个会话在面板上出现「同名两组」。现在脚本维护一份**会话别名表（显示名 → 真实会话 ID）**：解析出真实 ID 的消息顺手把「名字 ↔ ID」记下，同窗口拿不到 ID 的图直接复用；**按会话窗口解析一次**（先学 ID 再收集），并且**回退键后置合并**（持久层里历史遗留的 `name:` 条目一认出来就改写回真实 ID，读时纠正 + 写时迁移）。名字匹配按「精确 → 归一化（忽略空白与「（个体工商户）」这类尾注）→ 唯一包含」，**只要指向不唯一就放弃匹配**（宁可拆组也不把两个会话合成一个）。已知限制：工作台上的图片直链带签名会过期（过期后点开是 403，重新扫描取到的新地址照常可用）；**别的会话的图要么当时还在页面上、要么点开那个会话再扫一次**——工作台一次只把当前会话的消息给出来。**组内为什么按时间排**：会话分组给每张图都记了它所属消息的时间（`time`，与「文件名 → 会话」映射存在一起、同样持久化），面板据此在组内从新到旧排列（v26.10.16-v2；此前按体积排，用户反馈「想知道哪张是刚发的」）。时间取不到的图（未归属组，或那条消息本身没给时间）排在**有时间的图之后**、它们之间按体积倒序，因此**普通网页（无会话概念）上的排列与旧版完全一致**。**这些没有时间的图在面板上带一圈红影（v26.10.16-v3，用户要求）**，否则用户只看到它们被排在最后、却不知道为什么；红圈的判据与排序**共用 `sniffConv.timeOfItem` 这一个出口**（同为「会话时间 === null」），保证标红的恰好是被殿后的那批，两边口径不会分叉。

## 快速开始

### 1. 安装油猴扩展

在浏览器中安装 [Tampermonkey](https://www.tampermonkey.net/) 或 [ScriptCat（脚本猫）](https://scriptcat.org/) 扩展。

### 2. 安装脚本

**方式一：在线安装（推荐）**

访问脚本主页 [https://scriptcat.org/zh-CN/script-show-page/3650](https://scriptcat.org/zh-CN/script-show-page/3650)，点击"安装此脚本"按钮。

**方式二：手动安装**

1. 打开 [`dist/znhd.user.js`](dist/znhd.user.js:1) 文件，复制全部内容
2. 点击油猴扩展图标 → 创建新脚本
3. 粘贴内容并保存（Ctrl+S）

### 3. 开始使用

1. 访问征纳互动平台：https://znhd.hunan.chinatax.gov.cn:8443/
2. 脚本自动启动，右下角出现"征纳互动监控"浮动面板
3. 面板显示当前版本号、语音播报开关、设置和常用语入口

### 4. 开发与构建（改源码时）

脚本采用 Webpack + TypeScript 工程化开发（脚手架与 [douyu-helper](https://github.com/Eished/douyu-helper) 一致）。**源码在 `src/`，`dist/znhd.user.js` 是构建产物，请勿直接编辑**（下次构建会覆盖）。

```bash
npm install            # 首次：安装开发依赖
npm run build          # 生产构建：lint 修复 → 输出 dist/znhd.user.js
npm run dev            # 开发构建（watch，输出 dist/znhd.dev.user.js）
npm start              # 启动本地调试页 http://localhost:8080 并 watch（VSCode 里 Ctrl+Shift+B → start & dev）
npm run typecheck      # TypeScript 类型检查（strict）
npm run check          # 产物 + 服务端语法校验
npm run verify         # 无头 Chromium 端到端冒烟（面板/弹窗/传输助手三栏/常用语），CI 也跑这个
```

- **改版本号**：编辑 `config/common.meta.json` 的 `version`（格式 `YY.MM.DD-vN`，**零填充**；`N` 为当天第几次改动，**同一天内只递增 `-vN`、日期部分不动**），产物头部由构建自动生成。
- **本地调试**：`npm start` 后，按 `config/dev.meta.json` 中 `@require` 指向的 `dist/znhd.dev.user.js` 安装开发脚本（需在油猴中允许访问本地文件 URL）；改动 `src/` 会触发目标站点热重载。
- **发布**：push 到 `main` 后，`@updateURL`/`@downloadURL` 指向的 `dist/znhd.user.js`（GitHub raw 直链，不走 CDN 加速）即为最新产物，ScriptCat 自动同步。

## 功能详解

### 监控面板

脚本在页面右下角创建一个可拖拽的浮动面板，包含：

| 元素              | 说明                                                               |
|-------------------|--------------------------------------------------------------------|
| 版本号            | 显示当前脚本版本（如 `v26.10.12`）                                  |
| 状态行            | **行首在线指示灯（绿=在线 / 红=掉线）** + 单行文本：工作时段「当前等待人数：N 人」，非工作时段「当前非工作时段」（v26.10.15-v3 起由原「大字人数 + 在线/工作时段状态点」卡片压缩而来；v4 起行首恢复在线指示灯，详细状态见日志） |
| 🔊 语音 / 🔇 静音 | 一键切换语音播报状态，按钮颜色随状态变化（绿色=开启，红色=静音）   |
| 设置              | 打开设置弹窗，可配置工作时间、常用语数据源地址、CDN 开关，查看日志和脚本链接（中继服务器地址已移至「传输助手 → 第一栏底部设置」） |
| 常用语            | 打开常用语弹窗，加载并搜索常用语                                   |
| 传输助手          | 打开传输助手三栏窗口（手机 ↔ 电脑互传）                            |
| 图片嗅探          | 扫描当前网页图片，**按会话（纳税人）分组**（组内按消息时间从新到旧）预览 / 下载 / 打印 |

### 人数监控与掉线检测

- **等待人数检测**：通过 DOM 选择器 `.count:nth-child(2)` 获取当前等待人数
  - 人数为 0：记录成功日志
  - 人数 > 0：触发语音播报"征纳互动有人来了"
- **掉线检测**：检测 `.t-dialog__body__icon` 弹窗元素
  - 发现"掉线"文本时：记录错误日志并语音播报"征纳互动已掉线"
  - 面板状态行行首的指示灯会同步变红（绿=在线 / 红=掉线），详细状态以日志为准
- **工作时间限定**：非工作时间自动跳过检测，节省资源

### 语音播报

- 基于浏览器 `SpeechSynthesis` API，语言为 `zh-CN`，语速 `1.0`
- 内置**语音队列**：多条播报按顺序排队播放，避免同时播放导致冲突
- 静音状态下自动跳过播报，不清空队列
- 开启语音时自动初始化语音合成，解决浏览器 `not-allowed` 限制

### 常用语功能

1. 点击"常用语"按钮打开弹窗，自动从**设置面板中配置的常用语数据源**加载（默认 <https://cnb.cool/bbbbaa/work-about/-/git/raw/main/znhd/commonPhrases.yaml>，可在「设置 → 常用语数据源」处修改地址；仓库里的 [`public/commonPhrases.yaml`](public/commonPhrases.yaml:1) 是同步到该地址的源文件）
2. 支持**关键字搜索**：可按按键名称或内容过滤常用语
3. 点击常用语按钮后：
   - 自动复制文本到剪贴板（优先使用 `GM_setClipboard`，降级到 `navigator.clipboard`）
   - 播放提示音（`dida.mp3`）
   - 将文本追加到页面 TinyMCE 编辑器中（自动处理换行和空输入框场景）
4. 支持"重新加载"按钮手动刷新常用语数据（强制跳过缓存）
5. **本地缓存**：加载成功后缓存数据、数据源 URL 与时间戳；2 小时内再次打开弹窗（且数据源 URL 未变）直接复用缓存、不发网络请求，面板日志会提示「使用本地缓存」；修改数据源地址或点击"重新加载"会重新拉取
6. 常用语数据源地址可在「设置 → 常用语数据源」中自定义：粘贴你自己的 YAML 地址即可让团队使用各自的常用语；修改后需点"重新加载常用语"生效。**清空输入框后不会立即回填**——输入框保持为空，点击其他区域（失焦）后才恢复默认地址，避免用户正要粘贴新地址时被自动填上的默认值打断
7. **支持腾讯文档**（v26.10.17-v3 起；v26.10.17-v4 修复 401；v26.10.17-v5 支持列表）：地址填 `https://docs.qq.com/doc/<文档ID>` 即可直接用一份腾讯文档当常用语源
   - **解析规则**：按**一级标题**切分——每个一级标题作为一条常用语的**标题**，标题下（到下一个一级标题之前）的所有文本作为它的**正文**；**第一个一级标题之前的内容会被忽略**（通常放使用说明）。同名标题以后出现的为准
   - **列表会被保留**：有序列表渲染成 `1.` `2.` `3.`（支持字母 / 罗马数字 / 中文数字等编号格式），无序列表渲染成 `•` / `◦` / `▪`，嵌套层级用缩进表示；列表被普通段落隔开时序号重新从 1 开始（与 Word 一致）
   - **文档权限**：需设为「获得链接的人可阅读」。脚本用腾讯文档的**匿名只读**快照接口（`dop-api/opendoc`）取正文，不需要也不应该填账号 Cookie
   - ⚠️ **该接口会校验 `Referer`**：不带文档页地址时一律返回 `401`。脚本运行时已自动带上文档自身地址（同源），所以正常用不会碰到；**若日志报「HTTP 401：腾讯文档未开放匿名阅读」**，说明文档分享权限没开「获得链接的人可阅读」，去文档里改权限即可
   - **只支持「文档」类型**：智能文档（`/aio/`）、表格、幻灯片、PDF、思维导图都**不支持**——它们的正文接口要求登录态，匿名调用会被拒（`没有权限`）。链接写错或文档已删除时面板日志会提示
   - 生效方式与 YAML 相同：改完地址点「重新加载常用语」；同样走 2 小时本地缓存

### 日志系统

- 设置弹窗内嵌日志查看器，最多保留 20 条记录
- 日志按类型着色：
  - 🔵 信息（info）
  - 🟠 警告（warning）
  - 🟢 成功（success）
  - 🔴 错误（error）
- 自动过滤连续重复日志，避免刷屏

### 更新日志查看

- 面板「设置」→ 在 `[更新脚本]` 旁边的 **[更新日志]** 按钮，点击即在网页正中弹窗展示**最新 10 条**更新日志（右上角 × / ESC / 点空白处均可关闭）
- 日志内容来自 [`changelogs/`](./changelogs/) 目录下的**当月**日志文件（如 `changelogs/2026-10.md`）：脚本运行时用 `GM_xmlhttpRequest` 拉取，遵循设置里的「使用 CDN 加速」开关（开 = jsDelivr，关 = raw.githubusercontent）
- 弹窗底部「获取更多日志」跳转到当月日志文件的网页查看（历史月份见 `changelogs/` 目录）；弹窗底部会提示「共 N 条，已显示最新 10 条」
- 拉取失败（断网 / CDN 不可达）时弹窗内提示具体原因，仍可点「获取更多日志」在浏览器打开

### 传输助手（手机 ↔ 电脑互传）

适用场景：坐席在手机上有纳税人发来的图片（如身份证、资料截图），想快速发到电脑剪贴板，直接在征纳互动聊天框 Ctrl+V 粘贴；也可以把电脑上的文本 / 图片发给手机。

**窗口布局（三栏，v26.10.12-v4 起对齐微信桌面版暗色模式；v26.10.13-v1 起窗口整体缩小 10%（约 1166×756，v26.10.12-v5 曾放大 20%）；v26.10.13-v10 起按用户 excalidraw 白板稿做「圆角 + 层级」）**：

- **圆角与层级（v26.10.13-v10；v26.10.14-v1 起露出层与第一栏同色）**：整窗是「**窗口 → 内嵌圆角卡片 → 三栏**」三层——窗口外框 **14px 大圆角**；**第二栏 + 第三栏整体包在一张内嵌圆角卡片里**（10px 圆角 + 1px 浅色细边），卡片**右缘缩进 10px、下缘缩进 8px**，露出**与第一栏、标题条同色的窗口底色（#2E2E2E）**形成层级（v26.10.14-v1 前露的是 #383838，与第一栏有色差断层，应用户要求改齐）；**第一栏贴满窗口高度**不随卡片内缩。第三栏底部输入区是一枚**四边留白（左右下各 12px）的圆角浮起卡片**（12px 圆角 + 细边），不再是通栏面板。搜索框 /「＋」/ 会话条目 / 头像等内部控件统一 8px 圆角。圆角常量集中在 `wechatTheme.ts` 的 `RADIUS`（window 14 / panel 10 / card 12 / control 8），冒烟 `transferLayeredOk` 用几何 + 计算样式守着这套结构（含「窗口底色 === 第一栏底色」同色判据）。
- **标题条**：窗口顶部横条，**与第一栏同色（#2E2E2E，v26.10.12-v5 按用户要求不再用更淡的 #383838）**，右侧是**自绘关闭按钮**——鼠标悬浮整格变红（Windows 同款交互），点击关闭；点遮罩或按 Esc 也能关。antd 自带的 × 已关掉，关窗路径一条不少。设置 / 配对 / 企业信息等**子弹窗垂直居中**（v26.10.12-v5 起，不再顶着传输助手窗口上沿）。
- **第一栏（窄图标栏）**：微信式侧边栏，**只放图标不显示文字**——顶部 logo（头像位），中部入口从上到下是**对话 / 文件**（原「设备」已改名「**对话**」；未读消息数在「对话」图标右上角挂红色角标），底部**设置 / 企业信息**（企业信息里能看到中继地址、本机设备、在线手机、脚本版本，排查「连不上」时先看这里）。图标三态按微信规范（v26.10.12-v5）：
  - **默认**：白色描边线条图标、背景透明、无底色；
  - **选中**：图标变微信绿（只改填充色，**不叠加底板**）；
  - **悬浮（仅未选中项）**：外层出现一块**深色圆角方形底板**（带轻微浮起阴影），图标本身不变；选中优先于 hover——已选中的按钮悬浮只保持绿色图标；
  - 「对话」图标右上角保留**红色圆形未读角标**。
- **第二栏（会话列表）**：顶部**搜索框** + 紧邻右侧的「**+**」按钮（两者同底同高同圆角，v26.10.13-v10 起统一 8px 圆角），下方是列表。**「+」只在「对话」分组下出现**，是**配对**入口（手机扫码 / 打开链接即完成配对，配对入口统一收在这里）；**文件分组没有「+」**。列表条目为微信结构：左头像（设备专属底色首字符 / 聚合会话手机图标，带在线小绿点）、中间名称 + 最后一条消息预览（`[图片]` 或文本摘要）、右侧时间（今天 HH:mm / 昨天 / MM-DD）+ 未读红点角标；**有消息的会话按最后消息时间排在前面，纯在线设备随后**；选中条目用比栏底浅一档的底色高亮。**文件分组下点条目 = 筛选第三栏的文件视图**（v26.10.13-v5：点哪个会话就只显示哪个会话的文件，不会跳去会话窗口；顶部常驻「全部文件」入口可回到跨会话汇总）。
- **第三栏（聊天主区，三栏里最深）**：当前会话的聊天区（气泡左右分栏 + 底部吸附输入框，见下），未选中时显示空状态「暂无消息」。
  - **会话头部（微信式）**：左侧**对方头像 + 会话名称 + 在线状态**；右侧是**垃圾桶图标**（点击弹确认后清空这个会话）。
  - **消息气泡**：收到的（手机发来）靠左、**微信灰（#2F2F2F）底**，本机发出的靠右、**微信绿（#07C160）底 + 白字**，圆角；头像在气泡外侧。**消息按时间分隔条分组**：间隔超过 5 分钟的一组消息共用一条居中的灰色时间（今天 HH:mm / 昨天 / MM-DD HH:mm），不再逐条标时间（发送中 / 发送失败的状态仍标在气泡下；**v26.10.18-v1 起本机发出的图片 / 文件在「发送中」时气泡内另有一根上传进度条**，收到首个进度事件后出现、成功或失败后消失）。**两侧消息都按 Markdown 排版**（加粗 / 列表 / 表格 / 引用 / 代码块 / 链接；单换行原样保留），长文本自动换行。**图片气泡只显示图片本身、按图片自身尺寸显示（宽高比永远保持、完整可见不裁切）**，不拼文件名（文件名在「下载 / 打印」时才用到，按原名与 MIME 自动补扩展名）。
  - **设备会话**：图片消息**单击缩略图放大**（缩放 / 旋转 / 多图左右切换，预览底部工具栏末尾有**打印机图标**，点它用 react-to-print 打印**当前这张图的原图**，按 **A4 纸自适应且不带浏览器页眉页脚**——`@page { size: A4 portrait; margin: 0 }`，边距归零后浏览器没地方画标题/URL/日期，图片离纸边的留白由内容框 padding 提供；整张图等比缩放居中铺满 A4，不裁切、不跨页；⚠️ 打印对话框里的「缩放/适应纸张尺寸」仍会覆盖这个设置，如需完全按 CSS 出纸请把缩放选为 100%/无，对话框弹出期间请勿移除该图）；每张图**右下角**有三个**只显示图标**的按钮，**鼠标移到图片上才出现**，悬停时用提示文字说明：**复制**（把图片写入系统剪贴板，此步必须由一次点击触发，满足浏览器安全策略）→ 去征纳互动 Ctrl+V 即可、**下载**（把原图存为文件，自动按原名/MIME 补扩展名）、**垃圾桶**（红色，单独移除这张消息）。会话头部可一键**清空这个会话**（Popconfirm 二次确认）。
  - **文件视图**（第一栏「文件」）：传输过的内容按图片九宫格 + 文本列表展示，支持放大 / 打印 / 复制 / 下载 / 删除；**默认跨会话汇总（「全部文件」），点第二栏某个会话则只显示该会话的文件**（v26.10.13-v5，清空按钮也随之变成「清空本会话」）。
  - **底部输入区（微信原版结构；v26.10.13-v10 起为圆角浮起卡片）**：**固定吸附在聊天区底部、不随消息滚动**；一枚**四边留白（左右下各 12px）的圆角卡片**（12px 圆角 + 1px 细边，比聊天区略浅的实心底 #262626），浮在聊天区上。**工具栏图标行在输入框上面**：**表情 / 图片上传 / 文件**；下面是**多行文本框**，随内容自动增高、到 6 行封顶后改为框内滚动；**右下角是「发送」按钮**（发文本：Enter 发送、Shift+Enter 换行）。选图发送会先加入**待发列表**（点「发送 N 张图片」才真正上传，避免误选即发；逐张压缩后按序投递，带进度条，失败会标出第几张与原因）。选文件同理（**「待发送文件」列表 + 「发送 N 个文件」**），但**不做压缩**（PDF/压缩包/视频走 canvas 解码无意义）。
  - **任意文件传输（v26.10.14-v6）**：「**文件**」按钮可选**任意类型、可多选**（`accept` 留空）。中继按 MIME 分流——`image/*` 走图片通道（会话里是缩略图气泡），其余走**文件通道**（会话里是**文件卡片**：图标 + 文件名 + 大小 + 下载）。发送前只做体积预检（不压缩），**单次上限 100MB**（含图片，v6 起由 12MB 提高）。接收端可直接「下载」原文件；「全部文件」视图相应地分为**图片 / 文件 / 文本**三区。
  - **表情面板是在线表情包（v26.10.13-v3；v4 起「点一张直接发送」+ 悬停放大；v7 起两种自动收起；v26.10.14-v3 起走中继缓存 + 不进「全部文件」）**：点「表情」弹出 **8 个在线合集**（阿鲁和动物们 / 阿鲁日常 / 阿鲁日常 2 / 阿鲁与你 / 节日阿鲁 / 热词系列一 / tv_小电视 / 小黄脸，共 568 张），顶部切换合集、右侧「刷新」可强制重拉（清单本身缓存 12 小时）。**点一张表情就直接发给手机**（与「图片上传 → 发送 N 张图片」同一条链路：逐张压缩 → 进度条 → 投递；连点会排队逐张发出），**不再堆到「待发图片」里**；**点完一张面板立即收起**，**点面板之外的任何区域（消息区、输入框、窗口外）也立即收起**（v26.10.13-v7）。鼠标在格子上**停 0.5 秒**会弹出放大预览，预览显示中移到别的表情上会**立即换成那一张**，移出网格即收起。图片表情不依赖系统字体，Win7 上也是彩色的 —— 这是它比旧版 BMP 字符符号面板更好用的地方（旧面板已删）。
  - **表情包数据走中继缓存（v26.10.14-v3）**：整套表情包由**中继服务一次性下载到自己的磁盘**（`relay-server/data/emoji`，启动时后台预热 + 按需补图），脚本端与手机页都**优先同源请求中继**（`/emoji/packs.json` 清单 + `/emoji/<合集>/<文件>` 图片），不再各自跨网直连 CDN —— 既快（内网/同源、可并发）又不会触发 CDN 限流；**中继不可用（未部署 / 版本过旧 / 单张转失败）时自动回退 CDN 直连，功能不回退**。合集清单单一来源是 `relay-server/emoji-sources.json`（改合集只改那一处）。
  - **表情包不进「全部文件」（v26.10.14-v3，需求①）**：发送 / 收到的表情包图片带 `emoji` 标记，「文件」视图（全部文件与会话文件）据此**过滤掉表情包**，不混进正常传输的文件列表；会话聊天记录里表情照常显示（表情就是聊天内容）。

**工作流程**：
1. 每台电脑首次运行脚本时用 `crypto.randomUUID()` 生成并持久化一个**稳定设备 ID**（存在 `GM_setValue`，刷新/重开不变）；
2. 点第二栏「**+**」打开**配对窗口**：展示本机专属上传链接 `https://<中继服务器>/u/<设备ID>` 及对应二维码（**二维码由脚本端 qrcodejs 本地生成，无需服务器参与**），同时列出**已连接手机的数量与每台手机的设备 ID**（手机首次连接 / 断开都会写进运行日志），并提供**「发送测试图片」**按钮：一键从 `https://t.alcy.cc/fj` 取一张随机图，**当作手机上传**投到中继再回到本机，便于验证「收图 → 放大 → 打印」整条链路（需先配好中继地址）；
3. 手机浏览器打开该链接（或直接扫二维码）→ 进入**聊天窗**（v26.10.12-v5：与脚本端第三栏同款——微信暗色、气泡、底部输入区）→ 点输入区**图片按钮**选图/拍照（**支持多选**）→ 每张立即变成右侧绿色「发送中」气泡，手机端用 canvas 逐张自动压缩（最大边 1600px、JPEG 质量 0.75；**SVG 例外：跳过压缩原样直传**，保留矢量与 `image/svg+xml` 类型；**HEIC/HEIF 例外：手机端用 heic2any（公共 CDN）解码转 JPEG 后同样铺白底压缩直传**，确保电脑端含 Windows 无需额外编解码器即可打开，库缺失时回退原样直传）→ 逐张按序上传到中继服务器（服务端按设备维护 FIFO 队列，内存保护上限 100 条；**上传时带上本机手机 ID**，电脑端据此把内容归到这台手机的会话，v26.10.13-v6）；**发送状态标在气泡下方**（发送中… / 已发送 / 发送失败+原因；v26.10.18-v1 起上传中气泡内另有白色填充进度条，进度经 XHR `upload.onprogress` 逐事件回写），文本在输入框输入后 `Enter` 发送。
4. 电脑端脚本在**传输助手设置**（第一栏底部「设置」）填好中继地址后**默认自动**用 `GM_xmlhttpRequest` **长轮询** `/recv/<设备ID>` 取回内容（无需点击按钮；长轮询而非 WebSocket 是为了绕过征纳互动页面的 CSP 对 connect-src 的限制；v26.10.14-v7 起该长轮询还**顺路捎带在线手机名单**，手机上线/下线时由中继**主动结束**当前挂起的长轮询来推送，故在线状态是**秒级**刷新的，且不再需要额外的定时轮询请求；**取件失败时的重连是指数退避**（v26.10.14-v8：2s → 4s → 8s → 16s → 32s → 60s 封顶，成功即复位，429 直接跳到 60s；v26.10.15-v1 起**单次挂起时长 25s → 45s**（服务端上限 30s → 60s）—— 长轮询是闭环、请求数 ≈ 时长 ÷ 挂起时长，放宽后 8 小时请求数再降约 1000 次）—— 中继重启时不会出现所有客户端同节奏敲门把服务端再打回去）；
5. 收到的内容进入对应**会话**；窗口关着时按设置**自动打开传输助手**（默认开，可在设置里关掉——关闭后只累计未读角标，不打扰；窗口已开着则只累加，不强行切换会话）。在会话里点图片右下角「复制」写入剪贴板 → 去征纳互动 Ctrl+V 即可。

**发送到手机（反向）**：在设备会话底部输入区发文本、选图或**选文件**发送。发送目标由**选中的会话**决定：选**具体手机**的会话就只发那一台；多台在线时列表里会出现聚合会话「**手机**」，选中它等于**发给所有在线手机**。每台手机的 ID 都带**边框与专属底色**（同一台设备颜色恒定，不同设备颜色不同，最多 8 色循环），多台并排时一眼能区分是哪一台。手机页面会显示**本机（手机）ID** 与**已连接的脚本端设备ID**，便于和电脑端列出的 ID 对应上是哪一台。图片逐张顺序发送（一张成功再发下一张，保证到达顺序），单张压缩后上限约 100MB，超限即停止并提示已发几张；文件同样逐条顺序发送，但不压缩，单次上限也是约 100MB。**选完立即出「发送中」气泡 + 气泡内上传进度条**（v26.10.18-v1：待发项先全部落成气泡再逐个上传，上传进度经 `upload.onprogress` 逐事件写回气泡与状态小字；进度事件到达前只显示「发送中…」不画假进度条）。**手机端只挂一条连接**：一次 `POST /phone/poll` 同时完成「报活」与「等电脑发来的内容」—— 有内容立刻返回、没有则到期自动重连（v26.10.15-v2 起；此前是「8 秒心跳」+「长轮询」两条并行，故这次显著降低了手机的耗电与流量），页面打开约 1 秒内即显示「已连接」；若连的是**未升级的老中继**（没有该端点），手机会自动退回老模型，功能不受影响。

**会话归组规则（v26.10.13-v6 起按发送者归组）**：手机上传时会上报**本机手机 ID**，中继把它随内容回传（`from`），脚本据此把内容归到**那台手机自己的会话**——**两台及以上手机同时在线也各归各的**，不再全挤进聚合会话。只有识别不到发送者时（中继版本过旧、手机页版本过旧、或「发送测试图片」这类本机投递）才走旧规则兜底：恰好 1 台在线归那台的会话，否则归入聚合会话「**手机**」（头部会标注「无法识别发送设备时归在这里」）。选中一台**在线但无历史**的手机也会合成一条空会话，可直接发起发送（发送侧只要求对方在线，不要求有历史）。

**按用户隔离**：设备 ID 是每台电脑随机生成、几乎不可猜测的 UUID，因此 A 的电脑、B 的电脑各自持有不同链接与二维码，图片只进对应那台电脑，互不串。

**前置条件**：须自行部署配套 `relay-server`（见上方项目结构）。在「传输助手 → 第一栏底部**设置**」填写该服务的公网地址（如 `https://你的服务器:端口`，末尾不带 `/`）后，配对窗口里的链接与二维码才会生成。升级用户无需重填：第一次读取传输助手设置时，会把旧版存在主设置里的中继地址自动迁移过来。

**外观与设置隔离**：传输助手窗口 v26.10.12-v4 起**固定为微信桌面版暗色配色**（分层深浅 + 微信绿主色，嵌套 ConfigProvider 保证暗色算法与主色 token 都不外溢，与主面板、征纳互动页面无关）；它的设置项（中继地址、收到内容是否自动打开、清空全部传输记录）都存在独立的 `scriptCat_TransferSettings`，不写主设置的 `scriptCat_Allvalue`；入口也不共用——主面板设置菜单里不再有中继地址。

**会话持久化（v26.10.12-v5）**：对话内容（**含图片**）保存在本机 **IndexedDB**（数据库 `znhd-transfer`），刷新页面 / 重开浏览器 / 重启脚本后历史还在；**只保留最近 7 天**，超期消息自动删除（启动时、每小时各清理一次），图片 Blob 原样入库、载入时重建预览地址。隐私模式等 IndexedDB 不可用时静默退回纯内存态（行为同 v4），不影响收发。「清空全部传输记录」同时清掉持久化数据。

> 同一台电脑的链接可以被多台手机同时打开（例如家人同事一起用），它们是各自独立的「手机设备」；选中的手机若在发送瞬间恰好离线，内容会在中继保留 **60 秒**，它上线后即可取到。

> **手机页行为（v26.10.12-v5 聊天窗）**：电脑端发送的内容作为**左侧灰色气泡**出现在聊天窗里（图片可点开放大 / **打印**，文本气泡下有「复制」按钮）；手机发出去的图片 / 文本是**右侧绿色气泡**，发送状态（发送中 / 已发送 / 发送失败）标在气泡下方；本机发出的图片 / 文件上传中气泡内另有进度条（v26.10.18-v1）。

## 配置说明

### 脚本内部配置

[`src/lib/constants.ts`](src/lib/constants.ts:1) 中的 `CONFIG` 对象（只读的运行参数）：

```javascript
const CONFIG = {
    CHECK_INTERVAL: 3000,      // 监控检查间隔（毫秒）
    MAX_LOG_ENTRIES: 20,       // 面板最大日志条目数
    didaUrl: 'https://cnb.cool/bbbbaa/work-about/-/git/raw/main/znhd/dida.mp3', // 提示音文件（cnb.cool raw 直链，非 GitHub 链接 ⇒ resolveGithubUrl 原样返回）
    SPEECH_TIMEOUT: 15000,     // 单条语音播报超时保护（毫秒），防止队列卡死
    MAX_SPEECH_QUEUE: 10,      // 语音队列最大长度，超出丢弃最早
    SPEECH_QUEUE_TTL: 30000    // 语音队列消息有效期（毫秒），入队/播放前剔除过期内容
};
```

可用户配置项（语音开关、工作时间、常用语数据源、CDN 开关、日志自动刷新、嗅探阈值与嗅探后台预测量）存放在 [`src/lib/constants.ts`](src/lib/constants.ts:1) 的 `DEFAULTS` 中，运行时存于 `localStorage`（键 `scriptCat_Allvalue`），可在设置面板直接修改，无需改代码：

```javascript
const DEFAULTS = {
    voiceEnabled: true,   // 语音播报开关
    workingHours: {       // 监控时间段（单位：十进制小时，13.5 = 13:30）
        morningStart: 9, morningEnd: 12,
        afternoonStart: 13.5, afternoonEnd: 18
    },
    useCdn: true,         // 使用 CDN 加速（jsDelivr）加载项目内 GitHub 资源（目前实际生效的只有「更新日志」文件）
    // 注意：常用语数据源与提示音自 v26.10.10-v17 起都指向 cnb.cool 的 raw 直链（非 GitHub 链接，
    // resolveGithubUrl 原样返回、不受 useCdn 影响）。仍勿填成网页/仓库页面，否则会拉回整页 HTML 导致 YAML 解析失败。
    commonPhrasesUrl: 'https://cnb.cool/bbbbaa/work-about/-/git/raw/main/znhd/commonPhrases.yaml',
    logAutoRefresh: true, // 「运行日志」弹窗的自动刷新开关（开：新日志持续进来并滚到底；关：冻结快照便于翻看）
    sniffMinKB: 20,       // 「图片嗅探」面板的最小图片体积阈值（KB），小于阈值的图不显示也不参与批量下载
    sniffPreMeasure: true // 「图片嗅探」后台预测量（v26.10.14-v4）：开窗前就在后台量一遍大小，
                          // 打开嗅探窗口即刻出大小；关掉则只在开窗时测量（更省对页面图片服务器的请求）
};
```

> ⚠️ **中继服务器地址不在这里**：v26.10.12-v1 起它搬到传输助手自有设置（[`src/lib/transfer/settings.ts`](src/lib/transfer/settings.ts:1) 的 `DEFAULT_RELAY_SERVER`，默认 `https://znhd.122050.xyz`），存于独立的 `scriptCat_TransferSettings`，入口在「传输助手 → 第一栏底部设置」。旧版存在 `scriptCat_Allvalue.relayServer` 里的地址仅在本地从未存过传输助手设置时作一次性迁移种子读取，不再写回。

## 常见问题

### 语音播报不工作

1. 检查浏览器是否支持 Web Speech API（在控制台输入 `'speechSynthesis' in window` 应返回 `true`）
2. 确认面板上语音按钮显示为"🔊 语音"（绿色），而非"🔇 静音"（红色）
3. 浏览器可能需要用户首次交互后才能播放语音，尝试点击页面任意位置后再试

### 常用语加载失败

1. 检查网络是否能访问 `github.com`（常用语配置文件托管在 github）
2. 打开浏览器开发者工具（F12）→ Console 查看具体错误信息
3. 尝试点击常用语弹窗中的"重新加载常用语"按钮

### 监控不工作

1. 确认当前时间是否在工作时间内（上午 9:00-12:00，下午 13:30-18:00）
2. 确认征纳互动平台页面已完全加载
3. 打开设置弹窗查看日志面板，了解详细状态

### 传输助手用不了（手机连不上 / 收不到）
1. 确认已在「传输助手 → 第一栏底部**设置 → 中继服务器地址**」填写公网可访问的服务器地址（如 `https://你的服务器:端口`，末尾不带 `/`）；「企业信息」里可以一眼核对当前地址、本机设备 ID 与在线手机
2. 中继服务器需自行部署：进入 `relay-server/` 目录执行 `node server.js`（纯 Node 内置模块、零依赖，默认端口 5689，可用 `PORT` 环境变量修改；注：Node 端仍零依赖，仅手机端转换 HEIC 时需从公共 CDN 加载 heic2any，断网时 HEIC 回退原样直传）
3. 该服务器必须能从手机浏览器公网访问；仅本机 `localhost` 时手机无法连上
4. 点第二栏「**+**」打开配对窗口，用手机扫二维码或打开链接上传；中继地址填好后**脚本自动开始接收**（无需点按钮），收到后窗口自动打开，在会话里点图片右下角「复制到剪贴板」
5. **中继服务更新后必须重启**才会生效（常驻进程不热更）。正式部署：push 到 `main` 即由 GitHub Actions 自动同步到服务器并重启容器，无需手动操作；部署后 `curl http://127.0.0.1:5689/health` 返回的 `version` 与 `relay-server/package.json` 一致即生效。容器/手动场景：改过 `server.js` 后用 `docker restart znhd`（或 PM2/`systemd` 对应 restart，直接跑则停旧进程后重新 `node server.js`）。
6. **同一设备 ID 在多个标签页/浏览器同时开着会各自接收**：中继现已「广播」——每张图会同时推给所有在等待的接收端（你正在看的那个标签页一定会弹窗）。若只想在一个页面弹窗，关掉其余跑了脚本的标签页即可（例如调试用的 example.com）。
7. **收不到时先看归组**：v26.10.13-v6 起手机发来的内容**按发送者归到那台手机自己的会话**（多台在线也各归各的）；只有中继或手机页版本过旧、识别不到发送者时，才退回到「1 台在线归那台、否则归聚合会话「手机」」的旧规则——若内容落在「手机」会话里，先升级中继服务并刷新手机页面。

### 常用语点击后未填入编辑器

1. 确认页面中存在 TinyMCE 编辑器（输入区域）
2. 检查浏览器控制台是否有 iframe 跨域相关错误
3. 脚本会自动降级处理：优先使用 TinyMCE API，失败后直接操作 DOM
