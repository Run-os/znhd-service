### znhd.user.js v26.10.13-v3

- **表情面板换成在线表情包**：输入框的「表情」按钮不再弹 BMP 字符符号，改成你给的 **8 个在线表情合集**——阿鲁和动物们（36）、阿鲁日常（94）、阿鲁日常 2（56）、阿鲁与你（89）、节日阿鲁（31）、热词系列一（78）、tv_小电视（50）、小黄脸（134），共 **568 张**，全部来自 `cdn.klyang.com`：
  - 面板顶部是**合集切换**（可横向滚动）+「刷新」，下面是 8 列图片网格；图**分批下载**（每批 8 张），首屏很快出图，剩下的后台补齐；
  - **点一张表情 = 放进「待发图片」**（与「图片上传」完全同一条链路：逐张压缩 → 进度条 → 投递，带失败定位），点「发送 N 张图片」才真正发出去 —— 与微信「表情先落输入区」同义；手比下载快也没关系，点了会等这张下完再放进去；
  - 清单 JSON 缓存 12 小时（`localStorage` 键 `scriptCat_EmojiPacks`，面板上「刷新」可强制重拉）；
  - 清单与图片**都走脚本请求通道**（`GM_xmlhttpRequest`）——宿主税务页的 CSP 会拦掉 `<img src="cdn.klyang.com/…">` 这类外域图片（直接引用会是整片裂图）；
  - 图片表情**不受系统字体限制**，Win7 上也是彩色的（这正是它比字符符号好用的地方）；旧的 `chatEmojis.ts`（BMP 符号表）随之删除；
  - **Agent 对话的表情按钮禁用**（那条通道只收文本，与它旁边两个灰按钮一致，hover 有说明）。
- **WebP 图片原样直传**：压缩层新增 `isWebpLike` / `skipWebp`（默认跳过，与 SVG/GIF 同理：canvas 只能导出 JPEG，会丢**透明通道**——表情图铺白底后落在深灰气泡里就是一块白方块——以及动画帧）。
- 冒烟：新增 `emojiPackOk`（桩按 URL 作答：清单 JSON + 真 webp Blob，验「面板拿到清单与图片 → 点一张待发数恰好 +1」）；传输助手失败快照里一并带上表情面板字段。

### znhd.user.js v26.10.13-v2

- 修「编辑器误报」：产物头部注入 `// @ts-nocheck`（由 `getBanner` 生成，位于 `==/UserScript==` 之后）——VS Code 的 TypeScript 服务会对这个 3.7MB 的单文件产物跑一遍 JS 诊断，误报 3 条 `TS2451 无法重新声明块范围变量「Link」`。实测产物里**只有一处**真实的 `Link` 声明（antd 的 Typography.Link），另两处报错点实际落在 **JSDoc 注释**里的单词 `Link` 上，是超大文件上的解析定位错位（`node --check` 对该文件零语法报错）。加这行之后 tsc 对该文件的诊断由上百条归零。
- 冒烟新增**产物头部结构门禁**：`// ==UserScript==` 必须在文件第一行 + 元数据块之后必须带 `// @ts-nocheck`（防止将来重构 banner 时把注入弄丢）。
