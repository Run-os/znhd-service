#### 一、版式：2×2 → 一行四列（纯图标 + hover 文案）

- 面板 `PANEL_WIDTH = 340`，Card body padding 12 → 内容区约 316px；四列 `repeat(4, minmax(0, 1fr))` + gap 6 → 每按钮 **74px**。
- 原先「设置」独占 `color="primary" variant="solid"`，现四个按钮统一为 antd 默认样式。
- 自适应用 **CSS 容器查询**（组件内 `<style>{PANEL_CSS}</style>`，沿用 LogModal 的先例）：`.znhd-panel-btn { container-type: inline-size }` + `@container (min-width: 68px)`。
- **用户最终选择「只要图标，文案靠 hover」**，故当前 340px 下走纯图标分支；Tooltip 提供文案。

**⚠️ 容器查询按「内容盒」算，不是 border-box（本次踩到）**：按钮 74px 减去 padding 4×2 与 border 1×2，**只剩 64px**。我最初按 border-box 设阈值 68px，结果 64 < 68 → 文字始终不显示，表现为「自适应完全没生效」。
- 实测横排所需宽度：emoji 18px + 间距 2px + 「历史文件」4 字 × 11px = **64px**，正好卡边界会**折成两行**（`offsetWidth` 量到 22px = 每行 2 字）。
- 所以阈值取 68px（留余量），当前落在阈值下 → 纯图标。**面板若加宽到约 78px/按钮，文字会自动出现，无需改代码。**

**⚠️ 文字必须留在 DOM 里**：用 `display: none` 隐藏，**不能条件渲染**。冒烟是按 `textContent` 找面板按钮的（`clickByText('设置')`，包含匹配），改成 `{show && <span>…}` 会直接把断言打挂；它同时是纯图标态的可访问名。

**为什么用容器查询而非 JS 测量**：按钮在 grid 里宽度由栅格决定、与自身内容无关，所以不存在「隐藏文字 → 按钮变窄 → 反过来触发隐藏」的抖动回路。若用 JS 测自身宽度就会有这个回路。

#### 二、悬浮球拖动：必须区分「拖动」与「点击」

`usePanelDrag` 的处理器改为标题栏与悬浮球共用；悬浮球同时保留「点击展开」。

**⚠️ 核心事实（实测 Chrome 154）：`pointerdown` 里调用 `preventDefault()` 并不能阻止 `click`。**
- 原地点击序列：`pd|pu|click`
- 拖拽序列：`pd|pm×N|pu|click`
- 两者最后**都会**派发 click。不区分就会出现「拖完一松手面板被顺带展开」。

实现：`DRAG_THRESHOLD = 4px` + `movedRef` + `consumeDrag()`。悬浮球 `onClick` 先 `consumeDrag()`，是拖拽尾巴就吃掉这次点击；**取走即复位**，避免标记残留到下一次键盘触发的 click（键盘激活不经过 pointerdown）。

**⚠️ 顺带修掉一个被这次改动暴露的裁剪缺陷**：`clampPanelPoint` 的保留量原先恒为 `MIN_VISIBLE = 48`，而悬浮球只有 36px 宽 → `minX = -(36-48) = +12`，表现为「**悬浮球永远拖不到视口最左侧**」。改为 `Math.min(48, 元素宽度)`（Y 轴同理 `Math.min(HANDLE_MIN, 高度)`）。面板宽 340 > 48，**展开态行为与旧实现完全一致**，只有小尺寸元素受影响。

**新增 `clampHostIntoView(host)`**：悬浮球可以拖到贴边，但**展开回面板时按面板真实宽度重新裁回视口**，否则「从屏幕右下角展开」会出现面板大半在屏幕外、抓不回来。用 `prevCollapsedRef` 保证只在「收起 → 展开」这一跳时裁，避免挂载时多写一遍存档。

另外给 `BrandIcon` 的 `<img>` 加了 `draggable={false}`：悬浮球里的图片若被浏览器起原生 drag，指针序列会中断、拖拽失效。

#### 五、主面板缩窄 30%（340 → 238px）

用户要求「面板宽度缩小 30%」。340 × 0.7 = **238px**。

**⚠️ 宽度常量原先有两份，只改一处会出隐性 bug**：
- `MainPanel.tsx` 的 `const PANEL_WIDTH = 340`
- `panelHost.tsx` 的 `initialPoint()` 里**硬编码的 `340`**（`clampIntoView(pt, 340, 0)`，初始坐标粗裁剪）

只改前者的话，`initialPoint` 仍按 340 收一次坐标 → 存档在右侧的面板每次加载都被推到更左边，而随后的 `clampNow(false)`（按真实 238）**不会再把它推回去** → 表现为「面板每次加载都不在存档位置」。已把 `PANEL_WIDTH` 移到 `src/lib/ui/panelIds.ts`（该文件定位就是「UI 共享常量，避免循环依赖」），两处共用一份。

#### 六、v26.10.07-v4：日志弹窗「最新在底部 + 自动刷新开关 + 自动滚到底部」

用户要求（`feat:`）：① 最新日志展示在底部；② 新增日志持续自动刷新开关；③ 日志更新时自动滚至底部。经确认：滚动策略选「**总是滚到底**」，开关选「**持久化**」。**独立升版到 v26.10.07-v4**（按仓库「每次改动补一条」的约定，不与 v3 混在一起）。

**排序**：`logger.ts` 的写入顺序仍是「最新在前」，改为**渲染前反转数组**（`shown.slice().reverse()`）⇒ DOM 顺序 = 视觉顺序 = 最旧在上、**最新在下**。容器保持 `column`，**不是 `column-reverse`** —— 后者会把滚动原点翻到底部、阅读方向也跟着反过来。**这反转了 v26.10.06-v23 的决定**，文件头那段「勿改回 column-reverse」的注释已按新需求改写。

**开关**：底部状态栏加 `Switch`（默认开）。关掉时把列表**冻结**在关闭那一刻的快照。
- ⚠️ 冻结必须在**关掉之前** `setSnapshot(logEntries)`：否则 `source` 立刻切到空快照 → 列表瞬间清空。
- 持久化：`DEFAULTS.logAutoRefresh`（constants）+ `runtime.logAutoRefresh`（state）；`Allvalue = typeof DEFAULTS` 自动带上该字段，**`storage.ts` 零改动**。

**⚠️ 本轮最大的坑：首屏滚动不能只靠 `useEffect`。**
本弹窗用了 `destroyOnHidden`，antd Modal 是在 `open` **之后**才把内容挂进 DOM 的 ⇒ effect 触发时 `scrollerRef.current` 仍是 `null`，「打开就滚到底」永远不生效。
- 探针实测：17 行日志、`scrollHeight 630 > clientHeight 358`（确实可滚动），`scrollTop` 却**恒为 0**。
- 正解：**回调 ref**（`attachScroller`）在节点挂载那一刻滚 → `scrollTop = 272 = scrollHeight - clientHeight`（`distanceToBottom: 0`）。
- 回调 ref 依赖 `[autoRefresh]`：开关切换时回调身份变化 → React 重新挂载该 ref → 重新开启时自动回到底部。

**冒烟断言（24 → 26）**：
- `logNewestOnTop` → 反转为 **`logNewestOnBottom`**（末行时间戳 ≥ 首行）。
- `logListNotReversed` 保留、标签改写为「日志列表仍是 column（非 column-reverse）」—— 它锁的「DOM 顺序 = 视觉顺序」在新需求下依然成立，且正是防止有人用 `column-reverse` 去「实现」最新在底部。
- 新增 **`logAutoRefreshToggle`**（状态栏有 Switch、含「自动刷新」文案、默认 `ant-switch-checked`）。
- 新增 **`logAutoScrollBottom`**：⚠️ 先要求 `scrollHeight > clientHeight + 2`（真的可滚动），否则内容没超出高度时 `scrollTop` 恒为 0、断言永远为真。
- **这条断言自带一次真实的反向验证**：修复前它就是 ❌（探针实测 `scrollTop: 0`），修复后才 ✅ —— 确实能抓到「自动滚动没生效」这个 bug，不是假绿。
