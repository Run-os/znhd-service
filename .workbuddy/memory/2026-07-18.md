## 面板位置持久化 BUG 修复（重要）
- 用户反馈：移动面板刷新后位置没保存。核对 CAT_UI 源码发现 **createPanel 根本不提供 onDrag 回调**
  （库只认 point/appendStyle/footer/header/min/minButton/onMin/onReady/render/routes/style/validateMessages）。
  第一版用 onDrag 永远不触发，所以存不下来——是我的实现错误。
- 修复方案：移除无效的 onDrag；改用 MutationObserver 监听面板容器 div 的 style 变化（react-draggable
  拖拽时改写 left/top），读取 offsetLeft/offsetTop（视口坐标，与 point 同坐标系）实时 savePanelPoint。
  通过初始 point 的 left/top 字符串匹配定位面板容器；面板异步渲染故 setInterval 轮询(150ms,最多~10s)。
- 经验：CAT_UI 面板没有拖拽回调，要持久化位置必须自己监听 DOM。

## 面板位置持久化 第二次修复（真正根因）
- 第一次修复仍失败。真正根因：CAT_UI 面板用 react-draggable，拖拽时只改写**内部包裹层**的
  transform: translate(x,y)，根容器 left/top 不变。因此监听根容器 style 不触发、用
  offsetLeft/offsetTop 读到的永远是初始值——两条都错。
- 最终方案：①findPanelRoot 通过标题「征纳互动监控」向上回溯首个 position:absolute/fixed 的祖先
  定位面板根容器；②findDraggableNode 找内部带 translate 的层；③用 getBoundingClientRect() 读真实
  视口坐标（与 point 同坐标系）；④观测拖拽层 transform 变化 + mousedown/mousemove/mouseup 双保险保存；
  ⑤加载时若有存档直接写 root.style.left/top（拖拽层 transform 会复位0,0，故 left/top 即最终位置）。
- 加了 PDBG=true 诊断日志（[面板位置] 前缀），验证通过后可改 false。node --check 通过。

## 面板位置持久化 第三次修复（真正根因：Shadow DOM）
- 用户控制台报「未找到面板根容器」。核对源码发现 CAT_UI 面板 render 用 attachShadow({mode:"open"})，
  面板是自定义元素 <cat-ui-plan> 挂 document.body，内部 shadowRoot → div.container.arco → 面板主体。
  普通 document.querySelectorAll('*') 穿不透 shadow root，这才是前两次失败的真正原因。
- 最终方案：getShadowHosts() 收集所有带 .shadowRoot 的宿主 → findPanelRoot() 在 shadow 内按标题
  「征纳互动监控」+带内联 left/top 的 div 定位面板主体 → 监听整棵子树(subtree:true) style 变化 +
  mousedown 双保险 → getCurrentPoint 取带 transform 的拖拽层的 getBoundingClientRect 存真实视口坐标。
  恢复完全交给 createPanel 的 point:loadPanelPoint()，移除了手动改 left/top（多余且可能冲突）。
- 用户环境噪音：token/lock/MANIFEST-000001 Unable to create sequential file 是 Chrome 扩展/浏览器
  自身 IO 报错，与脚本无关。
- 待用户验证：控制台应出现「[面板位置] 已定位面板(Shadow DOM)...」，拖动+刷新确认是否记住。
