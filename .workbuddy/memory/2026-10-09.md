## shadcn 版 UI 的根因（已查明，重试时先看这三条）

1. **浮层挂错位置**：`getOverlayHost()` 当时 return `document.documentElement`，实测
   （Chrome 154 / React 19 / Radix Portal）**container 传 documentElement 会落回 `<body>`**。
   而税务页 `body` 带 `transform` ⇒ `fixed` 浮层的包含块变成 body 的盒子：
   弹窗 `top-1/2`、抽屉 `inset-y-0`/`h-full` 全部按 body 那几十像素算 ⇒ 弹窗挤在屏幕顶部、
   抽屉塌成一条 81px。**正解是自建一个挂在 documentElement 下的宿主 div**（本仓库
   `ImagePreview.tsx` 的 `getPreviewHost()` 早就是这么做并写在注释里的，迁移时被漏掉）。
2. **面板宿主漏了 `.znhd-root`**：shadcn 语义色变量定义在 `.znhd-root` 上（刻意不用 `:root`，避免污染宿主页），
   `panelHost.tsx` 建宿主 div 时没挂这个类 ⇒ `bg-popover`/`border-border`/`text-primary` 全部解析不到
   ⇒ 面板背景**透明**（宿主页文字直接透出来）、边框退回 currentColor（一圈黑边）、主色失效。
3. **类名笔误**：`bg-primary00` / `text-primary00` / `bg-primary0` / `text-destructive00`（7 处，无效类名，
   Tailwind 直接不生成）。这类笔误在 typecheck/lint 里都发现不了，只能靠**截图对照**。

**方法论**：这次三处硬伤都是「类名/变量写错但构建不报错」，靠 `npm run typecheck` 永远抓不到；
`tmp/ui-preview/`（gitignored）里我留了一套截图夹具（harness.html + shot.js + inspect.js），
能起本地服务 → 打开真实构建产物 → 逐屏截图，重试 shadcn 时可直接复用。

## ✅ 浮层容器修复（v26.10.09-v6）：antd 浮层被宿主 body 的 transform 囚住

**症状**：抽屉/弹窗的高度按 `body` 的盒子算而不是视口。敌意 harness（`body{transform:translateZ(0)}`）里
实测 `.ant-drawer` rect = `[0,0,1000,117]`（应为 800）；常用语按钮落在抽屉盒子之外、**鼠标事件到不了**
（hover 测不出来、点击区域也错位）；浮层还被压到面板宿主之下（body 的层叠上下文整体先被绘制）。

**根因**：`getOverlayContainer()` 返回 `documentElement` **本身**，而 antd/rc-util 的 Portal 收到它后
**实际把浮层挂进 `<body>`**（`document.querySelector('.ant-drawer').parentElement === body`）。

**修法**（`src/lib/ui/panelHost.tsx`）：改为返回**自建宿主 div** `#__znhd_overlay_host__`
（挂在 documentElement 下、自身无任何样式）⇒ 包含块回到**视口**。与预览层当年的 `getPreviewHost` 是同一办法。

**回归断言**（`scripts/smoke/znhd-smoke.html` + `run.js`）：`overlayViewportSized` —— 报告时刻所有
**可见**的 `.ant-drawer` / `.ant-modal-wrap` 必须 ≥ 视口高 − 2。判据刻意用**几何**而不是「容器是谁」
（portal 落点会随 React/antd 版本变化），且只统计可见浮层（antd 会把关闭过的留在 DOM 里，量到 0 高会假红）。

**证据**：修复前实测抽屉 117px、`elementFromPoint` 命中的是 `HTML`；修复后 800px、按钮可命中，
常用语 hover 8 项全过（`tmp/ui-preview/hover-check.js`，敌意 harness）。`verify` 三段 ALL-OK、`antd lint` issues: []。

⚠️ **反向验证没跑完**：本想 stash 掉修复确认断言会变红，两次都被下面的环境故障打断（build 挂掉 →
dist 停在「撤掉修复」那版）。故「断言有牙齿」的依据是上面**修复前的直接实测数据**（117px / 命中 HTML），
