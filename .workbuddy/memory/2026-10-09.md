### 踩到的四个坑（都是静态检查全绿、跑起来才炸）
1. **手机页白屏 `Cannot read properties of null (reading 'useRef')`** → 双份 React：
   `shared/` 在仓库根，Vite 按引用文件所在目录向上找 node_modules ⇒ `shared/ui/*` 用根 react、
   `web/src/*` 用 web/react。修法：`web/vite.config.ts` 加 `resolve.dedupe: ['react','react-dom']`。
2. **`@source '.'` 不递归** ⇒ `data-[state=checked]:bg-brand-500` 规则不生成。
   症状极难认：功能与 `data-state` 都对，只有颜色不对。改显式目录后正常。
3. **多弹窗并存时页签点不动** → 试过 Radix `modal={false}`（红项 6→22，已回退），
   真修法是 `Tabs.Content` 加 `forceMount`。Dialog 保持默认模态模式。
4. **主色断言基准值写错**：`#1677ff` = `rgb(22,119,255)`（`0x77`=119），我误记成 126，
   却以为是 oklch 转换误差并把容差放宽到 ±8。**放宽容差掩盖的是自己的笔误**，已改回基准 119 / ±2。

### 产物体积构成实测（用户问「用了 Tailwind 怎么还这么大 / 是不是借了 CDN」）
- **没借 CDN**：脚本头 `@require` 只有 js-yaml / qrcodejs / heic2any（运行时按需）。
  Tailwind 是**编译期**产物，CSS 以字符串形式打进包里，由 `GM_addStyle` 注入。
- **产物 425.4KB**（未压缩 source 合计 2391.1KB）。按未压缩 source 占比：
  `react-dom 51.9%` > `src 业务代码 15.5%` > `@radix-ui/* 13.7%` > `@floating-ui 7.0%`
  > `shared/ 4.2%` > `其它 node_modules 3.7%` > `react 1.6%` > **`Tailwind CSS 1.5%`** > `scheduler 0.8%`。
- ⚠️ 上面是 source 占比；CSS 是字符串**不参与 JS 压缩**，按最终产物算它约 **36.3KB ≈ 8.5%**（浏览器实测注入 37201 字符）。
- **结论：体积大头一直是 react-dom（约 52%）**，油猴脚本拿不到宿主的 React，只能整包打进去。
  Tailwind 不是负担，antd 移除反而省了 423KB（847 → 424）。
- 统计方法要点：直接按 `stats.modules` 分组会错 —— webpack 的 ModuleConcatenation 把 84 个模块
  内联进 `./src/index.ts`，会误判「业务代码占 55.9%」。**必须递归展开 `m.modules` 内层再分类**。
- 若将来要减重，最大可动的是 `@floating-ui`（167KB，只被 Tooltip 用）与 Radix；react-dom 基本无解。
