## relay-server 增加访问日志（排查"访问端口无日志"）
- 根因：`server.js` 只记录业务事件（[连接]/[发送]/[投递]/[断开]），**没有请求级访问日志**。
  浏览器直接 `GET /` 或 `GET /health` 只返回页面/JSON 但不写日志，所以"访问了端口却看不到任何输出"是正常的。
- 改动：在 `http.createServer` 处理器顶部加入请求级访问日志——`[访问] 方法 URL` + `res.on('finish')`
  输出 `[响应] 状态码 方法 URL (耗时ms)`。过滤掉高频长轮询/心跳路径（/recv、/phone/recv、/phone/heartbeat）防刷屏。
- 诊断价值：加日志后若访问仍无输出 → 是网络/反代/端口映射没把流量打到 5689（请求根本没到服务）；
  若有 [访问]/[响应] 输出 → 服务已正常收流量。
- 运行环境：用户在 1panel/node:25.9.0 的 node 运行时用 `npm start`（`node server.js`）跑该服务，监听 0.0.0.0:5689。

## 手机端卡"正在连接" / PC 看不到在线设备 / 手机发不出图（07-28 排查中）
- 现象：手机打开 `/u/<id>` 能加载页面（GET 通），但 `POST /phone/heartbeat` 心跳从未成功 → 无 `[连接]` 日志、PC `GET /phone/status` 返回 online:false、手机发图/文也失败。三个症状同源：手机→中继的 **POST 不通**。

## 真凶定案：模板字符串吞掉正则反斜杠（07-28 01:50 用真实浏览器定位）
- 用 browser-use 真实打开线上 /u/<id>：桌面 Chrome 同样卡"正在连接"，performance 资源为空（页面从未发过任何 fetch）。
- 注入 error 监听后刷新，抓到 `Uncaught SyntaxError: Unexpected token 'var' @ :150`。
- 根因：server.js 的手机页是**模板字符串**，内联 JS 写了 `match(/\/u\/(...)/i)`，模板字符串把 `\/` 转义成 `/`，
  浏览器收到 `match(//u/...)` → `//` 成行注释 → 语法错误 → **整段内联脚本死亡** → 心跳/轮询/发送全部不执行。
- 修复：模板内写成 `\\/`（输出 `\/`）。本地起服务抓渲染页确认输出正确，`new Function(渲染后脚本)` 语法通过。
- ⚠️ 教训（长期）：校验模板字符串内嵌的 JS，**必须校验渲染后的输出**，不能校验转义前的源码
  （之前 extract_check.js 校验源码通过，但浏览器拿到的是转义后的坏代码）。
- ✅ 02:05 用户重新部署后确认：手机端连接成功，整条链路（心跳/在线状态/收发）恢复正常，问题闭环。
