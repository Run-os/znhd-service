- 用户问：图片嗅探是不是打开嗅探窗口之前就已经在自动跑了。核查结论（**未改任何代码**）：
  - **开窗前已在跑**：资源表预收（v26.10.14-v2）——`src/index.ts` → `app()` 第一行 `startPerfCollect()`（扩容缓冲 20000 + `PerformanceObserver(buffered:true)` 持续抄录图片字节数进模块级 Map）；

## 14:20 图片嗅探「同一会话被拆成同名两组」修复（v26.10.14-v5）

用户给了实测证据（读 localStorage `scriptCat_SniffConvIndex`）：同一窗口的图被记成两种 ID —— 真实群组 ID（`GROUP…`）与回退键 `name:<显示名>`，显示名相同时面板上就冒出「同名两组」。

根因：会话 ID **逐张图片解析**，解析不出就退化成 `name:` 键且**再没机会改正**；当前会话更典型 —— `selectItem.conversationInfo` 拿不到 ID 时，它的名字当种子，把该窗口所有拿不到 ID 的图都推进同一个回退键。

修法（`src/lib/sniffConv.ts`，纯脚本端）：
- `AliasTable`：显示名 → 真实会话 ID；匹配三级「精确 → 归一化（去空白 + 去括号尾注）→ 唯一包含」，**指向不唯一一律放弃**。
- `buildConvContext` 走两遍：第一遍只认带真实 ID 的消息（学别名 + 纠正当前会话 ID），第二遍正式收集（同窗口无 ID 的图复用窗口 ID）。
- 回退键后置合并三处：`saveStoredConv` 写时迁移 / `loadStoredConv` 读时纠正 / `groupByConversation` 的 `convKey` 兜底 ⇒ 存量脏数据自动收敛。
- 持久层同桶新增 `aliases`（同 TTL；`CONFIG.MAX_SNIFF_CONV_ALIASES = 200`）。

冒烟：夹具改成「当前会话 conversationInfo 不给 conversationID + 当前窗口两条消息一条带 ID 一条不带」（+ 新图 `sniff-conv-c.png` 70 KB），新增 `sniffConvAliasOk`（组名不重复 + 3 组 + 第 0 组 2 张且 a/c 都在）；`sniffGroupOk` / `sniffGroupPersistOk` 张数随之更新。
