### 验证中发现的**预存严重回归**（非本次引入，已顺带修，1 行）
- server.js 手机页 `pollRecv`：`fetch(...).then(function(r){ if(ctrl) ctrl.abort(); return r.json(); })` —— 响应体未读就 abort，Chromium 实测 `r.json()` 抛 `AbortError`，被 `.catch` 吞掉后 1.5s 重连 → **手机端永远收不到电脑发来的图片/文本**（服务端已出队、电脑端显示发送成功、条目实际丢失）。系 v26.9.6-v3/v4 加 35s 看门狗时引入（当时只做了服务端冒烟，未验手机页收件）。
- 受控实验（页面内）：`fetch(...).then(r=>{ctrl.abort();return r.json()})` → `AbortError: The user aborted a request.`，耗时 1212ms（maxwait=1200）。
- 修法：只在「看门狗超时、原请求仍挂着」的 catch 分支 abort。`heartbeat` 的同款 abort 安全（只读 `r.ok`，不读 body），未改动。
