## v26.10.13-v3：表情面板换成 8 个在线表情合集

用户给了 8 个 `cdn.klyang.com/json/*.json`：清单结构 `{ name, type:'image', items:[{key,val}] }`，图片是 `cdn.klyang.com/emo/…/<key>.webp`（实测**静态** webp，单张 2–6KB；共 568 张：36/94/56/89/31/78/50/134）。

### 实现
- 新 `lib/transfer/emojiPack.ts`：`EMOJI_PACK_SOURCES` 写死 8 个合集；`loadEmojiPacks()` 并发拉清单、**单个失败跳过、全失败才 reject**，JSON 缓存 12h（localStorage `scriptCat_EmojiPacks`）；`loadEmojiBlob()` blob+objectURL 双缓存 + 在途请求去重（`Map`）。**全部走 GM_xmlhttpRequest**（宿主 CSP 会拦外域 `<img src>`）。
- 新 `ui/transfer/EmojiPackPanel.tsx`：合集 chips（横滚）+ 刷新 + 8 列网格 + 分批下载（每批 8 张，缓存命中的同步填）。点一格 → 立即用**已下好的 blob** 回调；没下好则等这张下完再回调（**不做 disabled**：点了没反馈更像坏了）。
- `ChatComposer`：删字符插入逻辑与 `theme`/`inputRef`，新增 `onPickEmojiImage` / `emojiDisabledReason`；Popover content 换成 `<EmojiPackPanel>`（**只在打开时挂载** ⇒ 不开面板不发任何请求）。
- `TransferDeviceChat`：`pickEmojiImage` 把 blob → `File`（mime 用 blob.type）→ 进 `pendingImages`，与「图片上传」同一条发送链路（objectURL 不 revoke，因为会话气泡会引用它）。
- `TransferAgentView`：不传回调 → 表情按钮禁用 + tooltip（与旁边两个灰按钮一致）。
- 删 `src/lib/ui/transfer/chatEmojis.ts`（BMP 字符表）；`icons.tsx` 里指向它的注释已改。
- 共享层加 **webp 原样直传**：`compress.ts` 的 `isWebpLike` + `prepare.ts` 的 `skipWebp`（默认 true）——canvas 只能导 JPEG，会丢透明通道（表情图铺白底 → 深灰气泡里一块白方块）与动画帧；且 2–6KB 的 webp 再压只会更大（即便不特判也会被「压不小就原样发」兜住，显式写出来是让语义明确）。

### 冒烟
- 桩：`cdn.klyang.com/json/*` → 返回 `{name, type, items:[2 张]}`（name 从 `EMOJI_PACK_NAMES` 取）；`cdn.klyang.com/emo/*` → **用 `canvas.toBlob(...,'image/webp')` 生成真 webp Blob**（代码会把 `blob.type` 当 mime 一路传下去，用 PNG 糊弄等于没测）。
- 用例（13150 开面板 / 13300 采样 / 13400 点第一张 / 13480 采样待发）：断言 = 面板有 ≥2 个 chips 且有选中态 + 格子 ≥2 且 **`<img>` ≥1（图真的下好了）** + 点后「已选 N 张」= 点击前 +1。

## v26.10.13-v2：产物注入 `// @ts-nocheck`（修 IDE 误报 TS2451）

用户贴来三条 IDE 诊断：`dist/znhd.user.js` 报 `TS2451 无法重新声明块范围变量「Link」`（61004 / 94144 / 104656 行）。

### 排查结论（**不是**真 bug，也不用改业务代码）
- 全文件**只有一处** `const Link`（61004 行，antd `Typography.Link` 的 forwardRef）；另两处报错位置精确落在 **JSDoc 注释**里的单词 `Link` 上（`*   Link,` 与 `* @import {Link, Parents} from 'mdast'`）⇒ VS Code 的 TS 服务在 3.7MB 单文件产物上**解析定位错位**。
- 佐证：文件无 BOM / 无 CR / 无 U+2028/U+2029；`node --check dist/znhd.user.js` 零报错；与本次尺寸改动无关（产物一直是这个体积，只是这次 present_files 打开了它才在 IDE 里报出来）。

### 修法
`config/webpack.config.base.js` 的 `getBanner` 末尾追加 `// @ts-nocheck`（位置在 `==/UserScript==` 之后、webpack bootstrap 之前 —— **不能放文件第一行**，脚本管理器的元数据块必须在首行）。实测：`tsc --ignoreConfig --allowJs --checkJs dist/znhd.user.js` 加之前报上百条（含 TS2451），**加之后 0 条**。
⚠️ `getBanner` 是模板字符串，注释里**绝不能出现反引号**（老陷阱同款）。

### 门禁
`scripts/smoke/run.js` 在「产物新鲜度门禁」之后新增**产物头部结构校验**（首行必须是 `// ==UserScript==` + 元数据块后必须带 `// @ts-nocheck`），顺手把该处重复的 `fs.readFileSync(BUNDLE)` 合并成一次读取。
