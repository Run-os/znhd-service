## 2026-10-10 · v26.10.10-v6：嗅探阈值只做过滤（不计数、不进全选/下载范围）

**用户诉求（m01267 原话）**：「1. 不需要在图片嗅探界面展示有多少张小于阈值  2. 勾选全选之后，再点击下方的"下载所选"按钮，它会将所有图片全部下载，包括了那些小于阈值的图片。这不应该，应该只下载没有被过滤的、选中的图片」。

**根因**：`SniffModal.tsx` 里「全选」与「下载所选」的范围都是 `kept`（= probed 里未被判定为非图片的全部），而 `kept` **含被阈值挡下的小图**（`known` 才是达标子集）。于是「全选 → 下载所选」把用户根本看不到的小图一起下载；标题「共 N 张」与头部「另有 N 张小于阈值」也都在数这批图。

**改法**（引入 `pickable = known.concat(unknown)` = 未被阈值过滤的图，作为**标题计数 / 全选 / 批量下载的唯一范围**）：
- `allSelected` / `toggleAll` / `doDownloadSelected` 三处从 `kept` 换成 `pickable`；下载用 `pickable.filter(selected)`，即使用户调高阈值后选中集里残留失效 key 也不会下载被过滤的图。
- 新增 `selectedCount`（`pickable` ∩ 选中集）驱动按钮文案与禁用态 —— 否则按钮会显示一个点下去却下不到那么多张的数字。
- 删掉 `belowCount` 与头部「另有 N 张小于阈值」；弹窗标题从 `kept.length` 改成 `pickable.length`。

**冒烟增量（CHECKS 46 → 47）**：`sniffUnknownKeptOk` 去掉「小于阈值另有计数」；新增 `sniffSelectScopeOk` —— 判据是**结构性恒等式**（不依赖夹具个数）：`selectAllCount === cards + unknownCount`，外加「面板不再出现『小于阈值』字样」「10 KB 的 ⑦ 不在任何卡片标题里」。夹具侧：poll 改成两阶段，第一阶段等测量完成，然后**直接点 `.ant-checkbox-wrapper` 里的 `input`**（`clickByText` 只认 BUTTON/A，点不到 antd Checkbox），250ms 后第二阶段重取快照读按钮文案「下载所选（N）」。run.js 的快照 dump 条件补上 `sniffSelectScopeOk`。
