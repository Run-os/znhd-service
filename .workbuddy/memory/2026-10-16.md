## 16:10 图片嗅探组内改按时间排序（v26.10.16-v2）

**用户要求**：会话分组**组内按时间**排，**最新的图片在前面**（此前组内按体积从大到小）。

**结论先行**：时间数据**本来就是现成的** —— 会话归属是逐张解析的，每张图都带着它那条消息的 `time`（`SniffConv.time`），且**已持久化**（`StoredRec.time`）⇒ 本版**只改排序**，协议/存储/采集链路零改动。

**实现**（`src/lib/sniffConv.ts` 的 `groupByConversation`）：
- 新增 `byTimeDesc`：`convOfItem(it) → .time` **比较时现取**（只是一次 `byStem` Map 查询，n ≤ MAX_SNIFF）—— 刻意不随分桶存一份，免得引入「T 的对象引用必须唯一」这个不成立就出错的隐含假设。
- **取不到时间（`null`）一律殿后**，它们之间退回老口径 `bySizeDesc`（原函数**降级为次级判据**，不删）。⇒ **未归属组整组无时间 ⇒ 普通网页上的排列与旧版完全一致**（这是本版的兼容性承诺）。
- `bucket.known` **和** `bucket.unknown` 两个数组都改用它（未知档渲染在达标图之后，口径不一致会让展开后顺序突变）。
- `ui/SniffModal.tsx` **只改注释**（渲染顺序本来就全从 `sections` 派生），但**下载兜底序号 / 打印顺序会跟着变**（统一取 `shownIndex`）。
- 组间排序未动：当前会话置顶 → 未归属殿后 → 其余按组内最新消息时间倒序。

**⚠️ 夹具必须让三种实现的顺序两两不同**（否则断言没有判别力）：原夹具里 `sniff-conv-a` 时间旧、体积最小、`<img>` 又在最前 ⇒「按时间」与「不排序（扫描序）」**同一个顺序**，对「排序被删」是瞎的。改成互斥三态：**a 时间最新（1700000003000）+ 体积最小（50KB）+ `<img>` 故意排在 c 之后**（c = 70KB / 1700000002000）⇒ 三种实现分别给 a,c / c,a / c,a。

**新增两条断言**（`znhd-smoke.html` report 字段 + `title` 链，**和** `run.js` 的 `CHECKS` + 失败快照链）：
- `sniffConvTimeOrderOk`（a 的位置严格早于 c，**且两张卡都要在** —— 只渲染一张时 `indexOf` 大小关系也可能成立）。
- `sniffConvNoTimeFallbackOk`（未归属组 40KB range 在 30KB head 之前 ⇒ 钉住兜底）。
  ⚠️ 后者的**归类**要说清：它**不是**本次改动的前后差异守卫（旧实现下它也绿），守的是「时间排序别误伤没有时间的图」。
