## 排查「部署后服务器 /opt/znhd-service 文件未更新」（01:17）
- 现象：用户贴的部署输出 `git checkout` 到 `554969d`（=本地 v2 提交），但 `/health` 返回 `"version":"26.7.28-v6"`（旧版），且服务器 `/opt/znhd-service` 文件未更新。
- 本地核实：`git status` 干净；`HEAD == origin/main == 554969d`；本地 `relay-server/package.json` = `26.7.29-v2`，且已推送 GitHub。即 GitHub 的 main 含 v2。
- 矛盾点：`554969d` 内含 v2，健康检查却报 v6 → 说明该输出大概率是较早一次运行（当时线上为 v6），或 `docker restart` 后容器未真正重载挂载代码。无论哪种，根因都是「工作树未被可靠强制对齐到 origin/main」。
- 修复 `deploy.yml` 同步段：在 `git checkout -f -B main origin/main` 之后追加 `git reset --hard origin/main` + `git clean -fd`，并在拉取后打印**工作树实际版本**（`grep '"version"' relay-server/package.json`），使后续运行可一眼确认工作树是否真更新（不再只依赖 /health）。
- 待用户：服务器执行诊断（`cd /opt/znhd-service; git rev-parse HEAD; grep version relay-server/; git remote -v; git status -s; docker exec znhd cat /app/package.json | grep version`）确认真实状态；把本 workflow 改动 commit+push 后重跑。

## 根因锁定：挂载源存在「嵌套 .git」（01:21 二次排查）
- 用户重申标准流程：本地改 → push GitHub → Action 同步到服务器；但 `/opt/znhd-service` 文件始终不更新。
- 重新精读 `deploy.yml` 后定位：最可能 concrete 根因 = **`/opt/znhd-service/relay-server/` 内有嵌套 `.git`**（1panel 建站或早期误 init 生成）。
  - 工作流在 `/opt/znhd-service` 又 `git init` 出根仓库 → 两个仓库并存；Git 把含 `.git` 的子目录当孤立/嵌套仓库，**父仓库的 checkout/reset --hard 不会触碰其子文件**。
  - 于是根仓库 HEAD 到 554969d（日志显示成功），但容器实际挂载读取的 `relay-server/server.js` 由嵌套旧仓库管 → 永远停在 26.7.28-v6（与早前 /health 报 v6 完全吻合）。
- 已给工作流加自愈：同步前 `find . -name .git -type d -mindepth 2` 找出嵌套 `.git` 并 `rm -rf`，确保 `/opt/znhd-service` 成为唯一仓库。
- 手动修复（服务器即时执行）：`cd /opt/znhd-service; rm -rf relay-server/.git; git reset --hard origin/main; git clean -fd; docker restart znhd`；之后 `cat relay-server/package.json` 应显示 26.7.29-v2。
- 验证命令：`ls -d .git` + `find . -name .git -type d -mindepth 2` + `git status -s | head`。
