## 最终生效方案：tar 管道绕过 bind 失联（02:39 五次排查）
- 用户确认挂载类型：三条均为 **bind 挂载（本机目录 => 容器路径，读写）**，`/opt/znhd-service/relay-server => /app`、run.sh、.env。排除 volume 假设。

- **最终修复**：重写重启段，去掉 docker cp，改用 tar 管道强制写入容器 /app（绕开 docker cp 路径解析坑 + bind 失联）：

  `（ cd /tmp/znhd-deploy && tar cf - . ） | docker exec -i "$CID" tar xf - -C /app` → `docker restart "$CID"`。
  tar 写入的正是容器当前看到的 /app（bind 失联时为孤儿目录，写入即更新为 v2），restart 后 node 重新加载 v2。两种挂载状态（失联/正常）下此写法都正确。

## 新增「使用 CDN 加速」配置 + resolveGithubUrl 函数（22:22 起）
- 用户需求：加配置「是否使用 CDN 加速」，并新建函数——输入 github 链接，开启 CDN 时输出 `https://cdn.jsdelivr.net/gh/用户名/仓库名@分支/文件路径`，关闭时输出原始 github 链接。
- 实现要点：
  - `DEFAULTS` 新增 `useCdn: true`；模块级 `let cachedUseCdn = !!_initAllvalue.useCdn`，在 `updateAllvalue` 中同步 `cachedUseCdn = !!newValue.useCdn`（`Allvalue` 是 DM 内 React state，非模块级，故用缓存变量供函数读取，保持函数签名只有 githubUrl 一个入参）。
  - 新增 `resolveGithubUrl(githubUrl)`（模块级）：支持 `github.com/.../blob/分支/路径` 与 `raw.githubusercontent.com/.../分支/路径` 两种输入；开启 CDN 用单次捕获正则把仓库后插 `@`（即 `gh/$1/$2@$3`，`$3` 兜住「分支/路径」整段，故 `refs/heads/main` 多段分支也正确）；关闭 CDN 的 github.com 输入转 `raw.githubusercontent.com`；非 GitHub 链接（npm CDN 等）原样返回。
  - 设置抽屉新增 `CAT_UI.Switch`「使用 CDN 加速（jsDelivr）加载资源」，prop `useCdn`/`onChangeUseCdn` 在 DM 内用 `patchAllvalue({ useCdn: !!v })` 接线。
  - 接入点：① `DEFAULTS.commonPhrasesUrl` 改存 GitHub 网页链接，`loadPhrasesData` 取用时 `resolveGithubUrl(cachedCommonPhrasesUrl)`，常用语抽屉「数据源」显示解析后实际地址；② `CONFIG.didaUrl` 改存 GitHub 链接，`playDidaSound` 取用时 `resolveGithubUrl(CONFIG.didaUrl)`。Viewer.js 的 npm CDN 不属 GitHub 资源，维持原样。
- 验证：独立 node 脚本测试 5 种输入（含 `refs/heads/main` 多段分支、简单 `main` 分支、npm 透传）全部正确；`node --check znhd.user.js` 通过。
