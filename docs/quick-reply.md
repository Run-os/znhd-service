# 飞书快捷短语（飞书规则表）

> v26.10.23-v1 起提供。会话输入区**上方**浮出快捷短语按钮（输入区外面上方，不是输入框里面），按当前对话内容自动匹配。
>
> **面向使用者的操作步骤（建表 / 授权 / 写标签 / 常见问题）见 [quick-reply-guide.md](quick-reply-guide.md)**；本篇是技术说明。
>
> ⚠️ 术语：这条链路一律叫「快捷短语」。页面右侧栏那套「常用话术」抓取叫「常用语」，是另一套机制（见 [phrases.md](phrases.md)）。
>
> 历史记录：[常用语快捷按钮开发方案.md](常用语快捷按钮开发方案.md) 是最初的需求/设计方案原文（当时的叫法还是「常用语快捷按钮」），仅作溯源，实现细节以本篇为准。

## 1. 它解决什么问题

坐席每天要回大量重复问题（「非正常户怎么解除」「申报期到几号」）。原有右侧栏「常用话术」
需要先打开侧边栏、搜索、再点卡片；这个功能把它压缩成**一次点击**：对话里出现「解非」，
输入区上方就浮出【非正常户解除】，点一下输入框里就是完整回复。

## 2. 规则表长什么样

使用者在自己的飞书账号下建一张多维表格，把**分享链接**粘进设置面板即可（v26.10.23-v2 起，不再写死；默认值 = 当前的「快捷发送常用语」表）。支持两种链接：

- wiki 分享链接：`https://xxx.feishu.cn/wiki/<节点>?table=tbl…&view=vew…`（点表格右上角「分享」复制出来的就是这种，脚本会自动把 wiki 节点换成真实表格 token）
- base 直链：`https://xxx.feishu.cn/base/<appToken>?table=…&view=…`

链接里不带 `table` 参数时自动用第一个数据表；不带 `view` 时读全表。

| 列名 | 类型 | 作用 |
|---|---|---|
| `标题` | 文本 | 按钮上显示的文字 |
| `标签` | 多选 | 命中关键词。对话文本**包含其中任意一个**即显示该按钮 |
| `内容` | 文本 | 点按钮后**整体替换**进输入框的文本 |
| `排除词` | 多选/文本（可选） | 对话文本包含其中任意一个 ⇒ 该规则不显示（排除优先于命中） |
| `是否常显` | 复选框（可选） | true = **忽略标签/排除词规则，始终显示**，排在快捷短语栏最前方（v26.10.25-v1） |

- **不需要**阈值、权重、必含词 —— 标签命中即显示（使用者 2026-10-23 定版）。
- `排除词` 列不存在时自动降级为「不排除」，不会导致整表读不出来。
- `是否常显` 列不存在或为空时按普通规则处理；值为 true 的规则：
  - 不吃标签/排除词匹配，**对话文本为空也显示**；
  - 排在快捷短语栏最前方（保持表内相对顺序），与普通命中之间用一条竖向分割线隔开；
  - 普通命中列表会按 id 去掉这些规则，避免同一按钮出现两次。
- 空行（标题与内容都为空）会被丢弃，不会产生空按钮。

### 魔法变量（v26.10.25-v1）

`内容` 列里可以写 `${变量名}`，点按钮写入输入框前在**点击时刻**展开（保证数值新鲜）：

| 变量 | 含义 | 取值链（宿主 Vuex store） |
|---|---|---|
| `${Active_Cnt}` | 正在对话人数 | ① `state.chat.groupInfoList` 是数组 → length；② 否则 `state.allChat.historyMsg` 是对象 → `Object.keys().length`；③ 都拿不到 → 0 |

- **未知变量名原样保留**（写错名不会吞字，输入框里能看到没展开的占位符）。
- 每次解析成功记一条日志 `正在对话人数（来源）：N 人`（只记来源与人数，不记对话文本）。
- 实现见 `src/lib/feishu/magicVars.ts`；宿主读取复用 `convText.ts` 的 `readVueInstance()`。

### 隐私信息表格（v26.10.25-v1，独立第二张表）

使用者另建一张多维表格（办公地点 / 办公电话等敏感速查条目），在设置面板单独配链接：

- **列约定与主表相同**（标题/内容），但**不参与标签匹配** —— 它就是个速查表，全部条目始终显示；
- 显示位置 = 快捷短语主栏**上方**的独立一行（左侧「隐私信息」标签，warning 色相 + 锁图标）；
- 链接配置独立（Allvalue `privacyTableUrl`，默认空 = 功能关闭），缓存独立
  （GM 存储 `scriptCat_PrivacyRules`），TTL 与主规则共用同一常量（5 分钟）；
- 「立即刷新规则」按钮**同时**刷新主表与隐私表：隐私未配置时静默跳过；主表成功而隐私失败只 toast 提示隐私失败；
- 「解除授权 / 作废并重新注册」会把隐私缓存一并清掉（token 没了它也读不了）；
- 点隐私按钮同样走「整体替换输入框」，魔法变量照常展开。

### 匹配的归一化

比较前双方都做：全角 ASCII 折半角 → 去掉所有空白 → 转小写。
所以「解 非」「解非」「解非 」都等价；英文不区分大小写。
**展示与写入输入框的始终是表里的原文**，不会被归一化改写。

`排除词` 是**子串**判断：写「已申报」不会拦掉「已经申报」。要拦长句就把完整片段写进去。

## 3. 授权（一次性）

设置 →「飞书快捷回复（输出框上方的快捷短语）」区块 →「授权飞书账号」：

1. 脚本调用 `POST accounts.feishu.cn/oauth/v1/app/registration`（`archetype=PersonalAgent`）
   发起**应用动态注册**，飞书返回一个 user_code 与授权链接 —— 这一步**没有任何凭证**，
   也不需要使用者去开放平台建应用。
2. 在浏览器/手机飞书里确认 → 脚本轮询拿到飞书为**这台机器**签发的 `client_id/client_secret`
   （存 GM 存储，不进脚本源码，不发给别人）。
3. 用这对凭证发起**设备授权**（`/oauth/v1/device_authorization`），申请
   `bitable:app:readonly wiki:wiki:readonly drive:drive:readonly search:docs:read offline_access`，
   使用者再确认一次 → 换到 `user_access_token`。

之后 access_token 2 小时、refresh_token **7 天滑动续期**（每次刷新重新计 7 天），
脚本在快过期时自动刷新，正常使用不会掉授权。

> 为什么是设备授权流：授权码流必须有一个可回调的 HTTPS 地址 ⇒ 等于要求每个使用者自建后端。
> 设备流把回调换成「用户在浏览器确认 + 客户端轮询」，天然无服务器。
>
> 已授权的机器只需重走第 3 步（凭证长期复用），不必重复注册应用。

### 从飞书直接选表（v26.10.24-v6）

设置面板的「从飞书选择表格」不再要求手粘链接，接口照抄飞书官方 CLI 的 `drive +search`：

```
POST https://open.feishu.cn/open-apis/search/v2/doc_wiki/search
{
  "query": "",                    // 可留空 = 按类型浏览全部
  "page_size": 15,
  "doc_filter":  { "doc_types": ["BITABLE"] },
  "wiki_filter": { "doc_types": ["BITABLE"] }
}
```

- **为什么不用 `drive/v1/files`**：那个只能列某个文件夹里自己空间下的文件，还得逐层翻；
  `search/v2/doc_wiki/search` 能搜到「别人分享给我、但不在我云空间里」的表，覆盖才完整。
- `doc_filter` 与 `wiki_filter` **各一份**：前者管云空间文档、后者管知识库节点，只给一边会漏。
- ⚠️ `doc_types` 枚举是**大写** `BITABLE`（v26.10.25-v1 修正）：曾发小写 `'bitable'`，
  服务端对所有请求一律回 99992402（field validation failed，泛化参数错误，与关键词长度无关），
  而且错误被误映射成「关键词太长」。现在 99992402 的文案改为
  「搜索请求被飞书拒绝（99992402 参数不合法）：请重试或重新授权后重试」。
- `query` 按 **Unicode 码点**限 30 字（服务端 99992402），代码用 `Array.from().slice()` 截断
  —— 普通 `slice()` 会把 emoji 的代理对切坏。
- 标题优先取 `title_highlighted`，用 `/<\/?hb?>/g` 清掉 `<hb>` 高亮标签。
- 返回的 `result_meta.url` **直接复用 `tableLink.ts`**：wiki 节点会被识别成 `/wiki/<token>` 再换
  `obj_token`，因此不需要为搜索单独写一套链接解析。
- scope 增加 `search:docs:read`。**加权限之前授权的 token 没有它** ⇒
  `getStatus().searchScopeOk` 读本地 `token.scope` 判断，false 时面板藏起选表按钮并提示重新授权
  （走「有凭证」分支，只多一次确认）。token 未记 `scope` 字段时按可用处理，避免因缺字段挡死功能。

## 4. 隐私

- 对话文本只从本机 `$store.state.chat.messageList` 读出，**只在内存里做子串匹配**；
- 唯一的网络请求是「读规则表」，只带 token、不带任何对话内容；
- 日志只记「来源 + 命中了几条」，不记对话正文；
- 凭证是明文存在脚本管理器的 GM 存储里（按脚本隔离，页面脚本读不到）。它只能读
  **使用者自己有权看**的多维表格 —— 换个账号拿同一个 token 也读不到别人的表。

## 5. 对话文本从哪来

优先级（`src/lib/feishu/convText.ts`）：

1. **Vuex**：`#app.__vue__.$store.state.chat.messageList` —— 当前会话的消息列表，
   从最新往回**只取 6 条有文本的消息**（`MAX_MESSAGES = 6`；图片/文件/撤回提示不占名额）。
   切会话自动跟着换，不受虚拟滚动影响。
   只看 6 条是刻意定版：把整场对话拼进来会命中过时关键词（半小时前聊「注销」、现在聊
   「解非」，不该同时出两个按钮）。
2. **DOM 兜底**：`quickReplyConversationSelector`（Allvalue 里的设置项），取该容器
   `textContent`。宿主改版导致 Vuex 路径失效时用这个应急。
   ⚠️ **设置面板尚未暴露这个输入框**，目前只能手工写进 Allvalue 存储。

两者都拿不到 ⇒ 返回空文本 ⇒ 不显示按钮（不报错、不影响打字）。

## 6. 刷新节奏

| 动作 | 间隔 | 说明 |
|---|---|---|
| 找输入框锚点 | 1s | SPA 换会话会整块替换输入区，靠轮询自愈 |
| 读对话 + 重算命中 | 3s | 文本指纹（长度+首尾 8 字符）没变就跳过 |
| 拉规则表 | 5min 缓存 | 由 `service.getRules()` 单点决定；设置里「立即刷新规则」强制回源 |
| 回源失败重试 | 60s | 掉线 / 未授权时最多 1 次/分钟，不会变成请求风暴 |

⚠️ **稳态下不会自动回源**：`mountQuickBar` 的 `ensureRules()` 开头就是「内存里已有规则就直接返回」，
所以 5 分钟 TTL 只在**内存副本为空**（首次加载 / 被清空）时起作用。改完表格想立刻生效必须点
「立即刷新规则」；否则要等下次页面加载且缓存已过期才会重拉（技术债，见 AGENT.md 快捷短语段）。

**规则副本如何保持同步**：按钮条不自己算 TTL，而是每个 tick 比对磁盘缓存的 `fetchedAt` 戳 ——
戳变了就换掉内存副本并清空文本指纹重算。所以设置里点完「立即刷新规则」或刚授权完，
**最多 3 秒**按钮条就会用上新规则（旧实现要等 5 分钟 TTL，点了刷新像没反应）。
回源失败时先用磁盘上的旧规则兜底（过期也用），总比一条按钮都不显示强。

## 8. 排障

| 现象 | 可能原因 |
|---|---|
| 输入区上方一直没有按钮 | 未授权（设置里看状态）；或最近 6 条对话没命中任何标签；或规则缓存为空（点「立即刷新规则」） |
| 面板报「没有读取这张多维表格的权限」 | 看错误下方的黄色提示框：表不在当前授权账号名下（别人分享的要加协作者）/ scope 没勾全（重新授权全部勾选）/ 链接贴错 |
| 授权页提示「你没有「XX的智能助手」的使用权限」 | 浏览器里登录的账号**不是注册应用时的那个账号** —— 动态注册出的应用是个人应用，只对创建者可用；点授权页里的「选择」切回原账号，或面板点「作废并重新注册」后用正确账号重走第 1 步 |
| 报 `access_denied：restricted by your organization's security policy` | 账号类型不允许给应用授予云文档权限：个人版 / 豆包等第三方登录的账号不支持（不是公司策略）；换有企业身份的飞书账号重新授权；若确是企业账号仍被拒，则是企业管理员禁用了第三方应用授权 |
| 第 1 步用错账号了，想重来 | 面板点「作废并重新注册」（清掉本机凭证），再点「授权飞书账号」重走第 1 步；飞书侧那个注册错的应用不会被删除，无副作用 |
| 提示 `app_scope_not_applied` | 授权时 scope 没勾全，重新授权 |
| 改了表、点「立即刷新规则」后按钮很快变了，但内容还是旧的 | 飞书侧可能命中了 view 缓存；确认改的是 `viewId` 对应的视图（当前默认视图之外的记录不会被读到） |
| 按钮出现了但点击无反应 | 页面还没有 TinyMCE 实例（`window.tinymce.activeEditor`），等页面进入会话再点 |
| 点按钮只弹「该规则没有填写「内容」列」 | 表里那一行的 `内容` 是空的 —— 按钮是靠 `标签` 命中显示的，但没内容可填 |
| 换了飞书表不生效 | 到设置里更新「规则表链接」并点「保存链接」；确认链接是那张表的分享链接（`/wiki/…` 或 `/base/…`） |
| 保存链接后报「规则表链接无法识别」 | 链接形态不认识：必须是 `/wiki/<token>` 或 `/base/<token>` 开头，可直接从飞书表格右上角「分享」复制 |
| 报「搜索请求被飞书拒绝（99992402 参数不合法）」 | 泛化参数错误（v26.10.24-v6 曾因 `doc_types` 小写全量触发，已修）：先重试；仍报就点「重新授权」换新 token；关键词别超过 30 字 |
| 排除词不生效 | 排除词是子串匹配，检查是否写成了更长的句子 |
| 常显按钮没出现 | 检查「是否常显」列：复选框要真的勾上（true）；文本列写 `true` / `是` / `1` / `√` 也认。常显随「立即刷新规则」同步（≤3 秒） |
| 隐私信息栏没出现 | 设置里「隐私信息表格链接」为空 = 功能关闭；配好链接后点「立即刷新规则」，或点隐私区块自己的「从飞书选择表格」 |
| `${Active_Cnt}` 填进输入框还是原文 | 变量名拼写必须是 `${Active_Cnt}`（大小写敏感、未知变量原样保留）；宿主 Vuex 字段取不到时展开为 0，真机取值正确性见 changelogs 的风险项 |
