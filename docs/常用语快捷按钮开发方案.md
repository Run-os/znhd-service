# znhd 油猴脚本 · 常用语快捷按钮功能 —— 开发文档

> 本文档用于交付给其他 AI 或开发者，据此实现/修改 `znhd` 油猴脚本的"输入框上方常用语快捷按钮"功能。
> 语言：简体中文。凡标注【已实测】的结论均已在真实环境中验证；标注【待验证】的需要实现时实测确认。

---

## 0. 一句话目标

在仿企业微信传输助手的输入框上方，根据**双方对话文本**匹配预设关键词，命中则显示"常用语快捷按钮"，点击按钮即把**输入框内容替换为预设回复**。

**示例**：对话中出现"解非" → 上方浮现【解除非正常】按钮 → 点击后输入框内容变为"非正常状态解除教程：xxx"。

---

## 1. 功能需求

### 1.1 触发条件
- 监听当前会话的双方对话文本（本机已抓取的消息，见项目 `src/lib/*` 的会话/消息结构）。
- 用对话文本对规则关键词做**子串/评分匹配**，命中则显示按钮。
- 匹配**只发生在本地**，对话文本绝不上传（硬约束）。

### 1.2 交互
- 输入框上方（输入框与工具栏之间）横向排布命中的快捷按钮，可横向滚动。
- 点击按钮 → 将输入框内容整体替换为按钮对应的 `reply` 预设文本。
- 未命中任何规则时不显示按钮（或显示为收起状态，由实现决定）。

### 1.3 规则管理
- 使用者可配置自己的规则表（关键词→回复）。
- 规则可**实时修改、免 push**（指改规则后脚本能拿到最新数据，无需改脚本代码）。
- 规则可**分发**给其他使用者；每个使用者**只配自己的规则**，且**无需每人搭建后端**。

---

## 2. 硬约束（不可违反）

| # | 约束 | 说明 |
|---|---|---|
| C1 | 不借助服务器 | 功能本身不能新增一个常驻后端/中间层服务器 |
| C2 | 对话隐私绝不上传 | 只读规则表数据，对话文本留在本地 |
| C3 | 规则实时改、免 push | 改规则→脚本即时生效，不重新发布脚本 |
| C4 | 可分发、每人配自己的规则 | 同一份脚本分发给多人，各自读各自的数据 |
| C5 | 无需每人建后端 | 使用者不需要自己搭服务器/写接口 |

---

## 3. 规则数据模型

规则表为结构化 JSON，建议直接存放于**飞书多维表格**（由使用者自己的飞书账号持有），每条记录对应一条规则：

```jsonc
{
  "keywords": ["解非", "解除非正常"],   // 命中关键词（任意命中即触发）
  "must_have": [],                       // 必须同时出现的关键词（可选，全部命中才加分）
  "exclude": [],                         // 排除词（出现则本条不触发）
  "reply": "非正常状态解除教程：xxx",     // 点击按钮后替换进输入框的文本
  "min_score": 1                         // 最低匹配分阈值（默认 1）
}
```

**匹配算法（已在早期确认，直接采用）：**
- 对话文本**直接对关键词做子串/评分匹配**（优于"先提关键词再匹配"）。
- 一级匹配（L1）：规则打分——`keywords` 命中一个得基础分；`must_have` 全部命中再加分；`exclude` 任一命中则整条作废；总分 ≥ `min_score` 才算命中。
- 二级容错（L2，轻量）：去空格、全/半角归一化、编辑距离（可选），用于容忍关键词里的空格/全半角差异。

## 4. 技术选型与决策记录

### 4.1 已否决的方案（及原因，勿再走）

| 方案 | 否决原因 |
|---|---|
| WPS 开放平台多维表格 API | 密钥放前端必泄露、WPS-3 签名、需企业认证、CORS/审核门槛高 |
| 腾讯文档智能表格（smartsheet） | OAuth2 + Client Secret + 应用审核门槛 |
| 逆向 kdocs 分享页数据接口 | 数据接口被前端签名墙（X-Pop-Token）保护，免登录 HTTP 复现不可行，需破解混淆 chunk+签名算法，且签名更新即失效、有平台条款风险（已实测） |
| 直接用 CLI（kdocs-cli / lark-cli） | CLI 是本地/Agent 命令行进程，油猴脚本在浏览器前端**无法调用**；且底层仍需应用凭证 |

### 4.2 选定方案：复用飞书 lark-cli 的登录方法（设备授权流 + 应用动态注册）

**核心思路**：飞书官方开源 CLI `larksuite/cli` 的登录实现本质是 **OAuth 设备授权流（RFC 8628）**，并附带一个**应用动态注册（App Registration）**能力。把它复刻进油猴脚本，可实现"使用者授权一次 → 拿到绑定本人飞书账号的 `user_access_token` → 用它读自己的飞书多维表格规则表"。

**为什么它满足全部硬约束：**

| 约束 | 满足方式 |
|---|---|
| C1 不借助服务器 | 设备流天然支持"无服务器/无回调 URL"，授权在浏览器完成 |
| C2 对话隐私不上传 | 对话文本在本地匹配，脚本只读规则表 |
| C3 实时改、免 push | 规则在飞书多维表格，脚本运行时实时读取 |
| C4 可分发、每人配自己的规则 | 脚本内置注册+授权逻辑，token 绑定使用者本人账号，各读各的表 |
| C5 无需每人建后端 | 通过"应用动态注册"，飞书为每个使用者动态签发应用凭证，无需使用者自己建应用 |

## 5. 关键实测结果【已实测】

对飞书端点做了一次无凭证实测，**动态注册（App Registration）无需任何应用凭证即可发起**，返回了完整的设备授权数据：

```
POST https://accounts.feishu.cn/oauth/v1/app/registration
body: action=begin & archetype=PersonalAgent & auth_method=client_secret & request_user_info=open_id tenant_brand

→ 200 {
  "device_code": "v1:eyJhbGciOiJFUzI1NiIs...",
  "user_code": "548P-2GL7",
  "verification_uri": "https://open.feishu.cn/page/launcher",
  "verification_uri_complete": "https://open.feishu.cn/page/launcher?user_code=548P-2GL7",
  "expires_in": 3600,
  "interval": 5
}
```

结论：**不需要 client_id/client_secret，任何客户端都能发起一个"应用注册"授权会话。** 使用者打开 `verification_uri_complete` 授权自己的飞书账号后，轮询即可拿到飞书为其动态签发的 `client_id/client_secret`（`archetype=PersonalAgent`）。

## 6. 飞书鉴权细节（源码提炼，可据此照做）

源码来源：GitHub `larksuite/cli`（main 分支），文件：
- `internal/auth/app_registration.go`（动态注册）
- `internal/auth/device_flow.go`（设备授权流）
- `internal/auth/paths.go`（端点路径）
- `cmd/auth/login.go`（登录编排）

### 6.1 端点清单

| 端点 | URL | 凭证 |
|---|---|---|
| 应用注册 begin | `POST https://accounts.feishu.cn/oauth/v1/app/registration` | 无 |
| 应用注册 poll | `POST https://accounts.feishu.cn/oauth/v1/app/registration` | 无（带 device_code） |
| 设备授权 | `POST https://accounts.feishu.cn/oauth/v1/device_authorization` | `Authorization: Basic base64(app_id:app_secret)` |
| 换 token | `POST https://accounts.feishu.cn/oauth/v3/token`【待验证端点确切路径】 | form 带 client_secret |
| 用户信息 | `GET https://open.feishu.cn/open-apis/authen/v1/user_info` | `Bearer user_access_token` |

> 注：源码中 token 端点为 `ep.Accounts + core.OAuthTokenV3Path`，`OAuthTokenV3Path` 结合飞书官方文档应为 `/oauth/v3/token`（`accounts.feishu.cn/oauth/v3/token`）。实现时实测确认。

### 6.2 完整授权流程（3 步）

**Step 1 — 应用动态注册（无凭证，已实测可发起）**
```
POST https://accounts.feishu.cn/oauth/v1/app/registration
form: action=begin
      archetype=PersonalAgent
      auth_method=client_secret
      request_user_info=open_id tenant_brand
→ { device_code, user_code, verification_uri_complete, expires_in, interval }
```
展示 `verification_uri_complete`（或用户码 user_code）给使用者，让其用飞书账号授权。

**Step 2 — 轮询拿动态应用凭证（无凭证）**
```
POST https://accounts.feishu.cn/oauth/v1/app/registration
form: action=poll
      device_code=<step1的device_code>
→ 授权中: { error: "authorization_pending" }（继续轮询）
→ 授权完成: { client_id, client_secret, user_info: { open_id, tenant_brand } }
```
将 `client_id` / `client_secret` 存本地（GM_setValue）。**这套凭证是飞书为"这一个使用者"动态签发的**，不进脚本源码，故不泄露给他人。

**Step 3 — 设备授权流，换 user_access_token（用 step2 的动态凭证）**
```
// 3a. 设备授权
POST https://accounts.feishu.cn/oauth/v1/device_authorization
Header: Authorization: Basic base64(client_id:client_secret)
form:   client_id=<动态client_id>
        scope=<所需scope，必须含 offline_access 才能拿 refresh_token>
→ { device_code, user_code, verification_uri_complete, expires_in, interval }

// 3b. 使用者再次授权（可用同一 verification_uri_complete 页面）

// 3c. 轮询换 token
POST https://accounts.feishu.cn/oauth/v3/token【待确认】
form:   grant_type=urn:ietf:params:oauth:grant-type:device_code
        device_code=<3a的device_code>
        client_id=<动态client_id>
        client_secret=<动态client_secret>
→ { access_token(=user_access_token), refresh_token, expires_in, refresh_token_expires_in, scope, token_type }
```
`user_access_token` + `refresh_token` 存本地。`expires_in` 默认约 7200 秒，`refresh_token_expires_in` 默认约 604800 秒（7 天），用响应里的实际值判断过期并刷新。

> DPoP：lark-cli 默认可用 DPoP 证明，但支持**纯 Bearer 模式**（`DPoPModeDisabled` / Bearer 回退）。油猴脚本优先走**纯 Bearer**（token_type=bearer），规避 DPoP 的密钥与时间同步复杂度。若飞书强制 DPoP，则需实现 DPoP 签名（RFC 9449），【待验证】。

### 6.3 刷新 token【待实测确认端点】
用 `refresh_token` 调飞书 refresh 端点（源码 `Refresh user_access_token` 接口），换取新 `user_access_token` + 新 `refresh_token`（refresh_token 一次性，需在过期前刷新）。

### 6.4 读取多维表格规则表

使用者把规则表建成**飞书多维表格**，把表 ID 配置进脚本设置（或授权后由脚本列出该账号有权限的多维表格，让使用者选择）。

```
POST https://open.feishu.cn/open-apis/bitable/v1/apps/<app_token>/tables/<table_id>/records/search
Header: Authorization: Bearer <user_access_token>
Body:   { "page_size": 500 }   // 分页拉全部记录
```
需要的 scope（权限）：多维表格读取相关，如 `bitable:app:readonly`。【待验证】动态注册的 PersonalAgent 应用是否默认授予此 scope；若不授予，需引导使用者在授权时勾选，或脚本用 `scope` 参数显式请求。

## 7. 前端实现要点（油猴 / Tampermonkey / ScriptCat）

- **跨域**：用 `GM_xmlhttpRequest`（扩展特权上下文，不受同源策略限制）调用上述飞书端点。需要在脚本 `@connect` 白名单加入：`accounts.feishu.cn`、`open.feishu.cn`。
- **存储**：所有凭证（动态 client_id/client_secret、user_access_token、refresh_token）用 `GM_setValue` 存本机；规则表数据可缓存 `GM_setValue` 并定时刷新。
- **授权入口**：脚本设置面板加"授权飞书"按钮 → 发起 Step1 → 弹窗展示授权链接/用户码 → 使用者授权 → 脚本后台轮询完成 Step2/Step3 → 存 token。
- **token 状态**：启动时检查 token 有效性，过期自动刷新；刷新失败则提示重新授权。
- **UI**：快捷按钮条用项目既有 Vue3 + daisyUI 5 + Tailwind v4 组件风格（参考现有常用语相关 UI，见项目 `src-vue/` 与 `src/lib/phrasesZnhd.ts`）。

## 8. 待验证事项与风险（务必先测，再封版）

| # | 事项 | 类型 | 影响 |
|---|---|---|---|
| V1 | 动态注册的 PersonalAgent 应用**是否默认授予多维表格读取 scope** | 【待验证】 | 决定方案是否成立；不授予则需引导授权勾选/自建应用 |
| V2 | token 端点确切路径（`/oauth/v3/token`） | 【待验证】 | 需要按源码/官方文档实测 |
| V3 | 前端 `GM_xmlhttpRequest` 直接调飞书端点是否被风控/拦截（Origin 校验） | 【待验证】 | lark-cli 是 Go HTTP 客户端（无 Origin），GM_xhr 也应无 Origin，需实测 |
| V4 | 是否强制 DPoP | 【待验证】 | 强制则需实现 DPoP 签名，复杂度上升 |
| V5 | **灰色地带风险**：应用动态注册是飞书为"官方 CLI/AI Agent"设计的机制，用于第三方油猴脚本分发属机制滥用，飞书可能风控、变更接口、封禁 | 风险 | 非契约性稳定通道，需接受此风险或备选方案 |
| V6 | 每个使用者需有飞书账号 + 首次过一遍"注册+授权"流程 | 门槛 | 影响上手体验 |

## 10. 验收标准

1. 首次授权：使用者点"授权飞书"→ 跳转授权 → 脚本拿到 `user_access_token` 并存本地，无需使用者建应用、无需后端。
2. 规则读取：脚本能读到该使用者飞书多维表格里的规则记录。
3. 匹配：对话含"解非"→ 输入框上方出现【解除非正常】按钮。
4. 替换：点击按钮 → 输入框内容变为"非正常状态解除教程：xxx"。
5. 隔离：A 使用者的 token 读不到 B 使用者的数据。
6. 隐私：对话文本无任何网络请求上传（可用 DevTools 网络面板确认）。
7. 刷新：token 过期自动刷新，无需重新授权（或降级为提示重新授权）。
